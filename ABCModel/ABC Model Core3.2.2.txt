## 2.8 時間構造（フレーム・持ち越し・観測融合）【v3.2.2 新設】

> **本節の位置づけ**：v3.2.1 では「§7.3 手順1＝毎フレーム観測を受領」と「§11.6＝ΔX'' を次フレームへ持ち越し」が両立せず矛盾していた。v3.2.2 は **「Core が状態を所有し、観測は上書きせず融合される」** 方式で解消する。

### 2.8.1 フレーム

*   **1フレーム ＝ Core の 1回の step 実行**。時刻 `t` は 0 起点の**単調増加整数**。
*   フレームと実時間の対応（`frame_policy ∈ {event, interval, hybrid}`）は**観測層が宣言**する（観測層仕様 §3）。Core は `t` の単調性のみを要求し、実時間には依存しない。
*   観測が無いフレーム（欠測フレーム）でも step は実行できる（§2.8.3／§2.8.4 の欠測規則に従う）。

### 2.8.2 持ち越し（carry）と commit

**原則：持ち越すのは「内在値＋離散State」であり、投影・相互作用の結果（`X'`/`X''` の連続値）は持ち越さない。**

commit（§7.3 手順13）で以下を次フレームへ持ち越す：

```
vX_carry := vX_t                          （融合後の内在値｜§7.3 手順2 の出力）
ΔX_carry := ΔX_t − 1·𝟙[TR-6 発火]         （内在値。TR-6 の減衰は内在側にも適用｜下限0）
StateX_carry := StateX''_t                 （TR 適用後の離散State＝時間方向の記憶）
vE_carry := vE_t,  ΔE_carry := ΔE_t,  StateE_carry := StateE_t   （E∈{E0..E3}）
```

**設計根拠（規範）**：EF投影（§6）と相互作用I（§7）は「**重畳**（フレーム局所のオーバーレイ）」であり、
その出力 `vX''` を carry すると**外部補正が毎フレーム複利で蓄積して発散する**
（例：E2 存在下で `vB'' = vB + 0.5·adjE2` が commit → 次フレームその値にまた `+0.5·adjE2` → 飽和。
参照実装で確認済み——一度 Runaway に入ると解除閾値に永遠に到達しない）。
`X'`/`X''` は毎フレーム、carry された内在値＋EF から**再計算**する。
時間方向の記憶は **離散State（および ΔX_t・各カウンタ）** が担う。

付随して持ち越す内部状態：
`ZeroLock`／`cooldown[TR_i]`／`base_streak`（§11.2）／`run_streak_X`・`calm_streak_X`（§8.0）／
`zero_low_streak`（§8.1）／`EMA_vA`／`runaway_absent_count`（§8.2.4）／`ef_missing_count_E`（§2.8.4）

### 2.8.3 観測融合（A/B/C）

観測層から `Observation`（欠測可）を受領する。各チャネルの観測は `(vX_obs, ΔX_obs, cX)`、
`cX ∈ [0,1]` は確信度。**`cX < θ_conf`（既定 0.3）のチャネルは欠測扱い（`cX := 0`）**。

*   **v（EMA融合）**：
    `vX_t = vX_carry + λ_v · cX · (vX_obs − vX_carry)`（`λ_v ∈ [0.3, 0.8]`、既定 **0.6**＝観測優位）
    **欠測時（中立への微緩和）**：`vX_t = vX_carry + ρ_core · (v_neutral − vX_carry)`
    （`ρ_core=0.1`、`v_neutral=1.0`｜観測が途絶えた内在値はゆっくり中立へ戻る。
    これが無いと、無観測のまま Runaway が永続する吸収状態が生じる——参照実装で確認済み）
*   **Δ（max融合）**：
    `ΔX_obs` 欠測かつ `vX_obs` ありの場合は導出：`ΔX_obs := min(2, κ_jump·|vX_obs − vX_carry|)`（`κ_jump=1.0`）
    `ΔX_t = max( ΔX_carry, ΔX_obs )`
    両方欠測時：`ΔX_t = ΔX_carry`（Δ の減衰は TR-6 のみが担う）
*   **State**：**A/B/C の State は観測から受け取らない**。`StateX_t` の初期値は `StateX_carry` とし、
    §8.0（Runaway判定）・§8.1（Zero判定）で Core が更新する。

**融合の設計意図**：
v の EMA 融合により観測は carry を「引っ張る」が上書きしない。Δ の max 融合により、
**TR-6 の減衰（§11.6）は観測が静かな限り持続し、新たな動揺の観測は即時反映される**。
これが v3.2.1 の矛盾の解消方式である。

### 2.8.4 EF の融合と減衰

*   **観測あり**：v/Δ は §2.8.3 と同一式で融合するが、**EF は `λ_EF=0.8`** を用いる
    （外的要因は「事実の測定」であり、内面より慣性を小さく＝観測追従を速くする）。
    `StateE_prop`（観測層の提案）がある場合はそれを採用し、
    無い場合は §8.0 の Runaway判定を E チャネルにも適用する。
*   **欠測**（当該フレームで E チャネルの観測なし）：
    `vE_t = ρ_EF · vE_carry`（`ρ_EF=0.7`｜外的要因は再観測されない限り減衰する）
    `ΔE_t = max(0, ΔE_carry − 1)`
    **2フレーム連続欠測**で `StateE := Normal`
*   `w_zero_ext` は観測層の `zero_ext_flags`（E0..E3 の各成立フラグ）から §8.1 の式で算出。欠測時は 0。

### 2.8.5 初期フレーム（t=0）

*   `carry` は存在しないため、観測値で初期化：`vX_carry := vX_obs`（欠測チャネルは `v=1.0`）、
    `ΔX_carry := ΔX_obs`（欠測は `0`）、`StateX_carry := Normal`（全成分）
*   `EMA_vA(0) = vA''_0`、`ZeroLock=0`、全カウンタ=0、全 cooldown=0

## 2.6 Bサブタイプ（評価方向の分類）

**目的**：Bにおける評価基準の参照方向を保持

### 2.6.1 定義

### 2.6.3 運用

*   推定・可視化層で保持
*   TR・State離散・Rラベルには非介入

## 5. RuinScore（危険度）

**前提**：RuinScore は **TR 適用後の `vX''/ΔX''/StateX''`**（Core）および §6.2（E）を入力。

**成分X別**：

*   `RuinScoreX_base = w_vX·vX + w_ΔX·ΔX + w_sX·StateMagX`
    *   **素の値域**（clamp前）：`X∈{B,C}` は `[0,6]`／**`X=A` は `w_vA=-1` のため `[-2,4]`**
    *   `X∈{E0,E1,E2,E3}` は `[0,6]`（外部重みは全て +1）
*   `φ_soft = β·𝟙[ΔX=Spike ∧ StateX=Runaway] + ζ·𝟙[StateX=Zero]`
*   `RuinScoreX_pre = RuinScoreX_base + φ_soft`
*   **強制境界**（スコア段階のみ適用）：
    *   `ΔX=Spike ∧ StateX=Runaway → RuinScoreX_pre := max(…, 5)`（R2以上）
    *   `StateX=Zero → RuinScoreX_pre := max(…, 3)`（R1以上：Zero-Guard）
*   `RuinScoreX = clamp(RuinScoreX_pre, 0, 6)`
*   `RuinScore_core = max(RuinScoreA, RuinScoreB, RuinScoreC)`
*   `RuinScoreE = max(RuinScoreE0, RuinScoreE1, RuinScoreE2, RuinScoreE3)`
*   `RuinScore = max(RuinScore_core, RuinScoreE)`

**設計上の含意**：A は `vA` が高いほどスコアが下がる（保護的）。ただし `ΔA=Spike ∧ StateA=Runaway` の強制境界は A にも適用され、`vA` の高低に関わらず R2 以上になる。これは意図された挙動である。

5.1 **重みの既定**：`w_vA=-1`、`w_vB=1`、`w_vC=1`／`w_ΔX=w_sX=1`（X∈{A,B,C}）
5.2 **推奨初期値**：本番 `β=0, ζ=0`／分析可視化 `β=0.5, ζ=0.5`
5.3 **手順（順序厳守）**

1.  Core各成分の基本和（`X''` を入力） → `RuinScoreX_base → φ_soft → RuinScoreX_pre`
2.  成分別の強制境界適用（`max(…, 5/3)`）
3.  成分別 `clamp(0,6)`
4.  Core統合：`RuinScore_core = max(A,B,C)`
5.  外部要素（§6.2）→ `RuinScoreE`
6.  CoreとEの最大：`RuinScore = max(R_core, R_E)`
7.  **二峰性の補足（任意）**（§6.4）
8.  終端強制境界再適用（maxのみ｜冪等）
9.  最終 `clamp(0,6)` → **`R_cont` を確定・保存**（§5.5.1）→ 整数化（Rバンド丸め）

5.4 **Rレベル**：R0=0–2／R1=3–4／R2=5／R3=6
5.5 **丸め（Rバンド）**：
`R_cont`（§5.3 手順9 時点の連続値）に対し、

*   **R0帯**：`R_cont < 2.5 → 2`
*   **R1帯**：`2.5 ≤ R_cont < 4.4 → 4`
*   **R2帯**：`4.4 ≤ R_cont < 5.4 → 5`
*   **R3帯**：`R_cont ≥ 5.4 → 6`

> **閾値の非対称性**：R1→R2 境界は `4.4`、R2→R3 境界は `5.4`。四捨五入ではなく、**上位帯へわずかに入りやすくする（安全側＝過検知側に倒す）意図的な非対称設定**である。R0/R1 境界のみ `2.5`（中点）を用いる。
> ※ この解釈は数値配置からの推定を含む。設計意図と異なる場合は本注記を修正のこと。

### 5.5.1 R_cont の保持（必須）

Rバンド丸めは**代表値への写像であり情報を失う**（例：`R_cont=0.0` も `R_cont=2.4` も同じく `R=2`）。
そのため **`R_cont` を監査フィールドに必ず保存する**（§5.7 / §14）。
低リスク域（R0帯）の推移追跡・時系列可視化・閾値チューニングは `R` ではなく **`R_cont` を用いること**。

5.6 **強制境界**：`Spike×Runaway ⇒ ≥5`／`Zero ⇒ ≥3`
5.7 **監査フィールド（例）**：

```
r_explain = {
  top_source: "A|B|C|E0|E1|E2|E3",
  forced: ["ZeroGuard" | "SpikeRunaway" | ...],   // 空配列可
  r_cont: <float>,        // §5.5.1（必須）
  r_band: 2|4|5|6,        // Rバンド丸め後
  r_level: "R0|R1|R2|R3",
  blend_used: bool,
  soft_used: bool
}
```

※ `B_type / wB` は RuinScore に直接介入しない

## 7. 相互作用の適用順序と更新

### 7.1 I 適用（EF重畳後の vX'/ΔX'/StateX'｜同一時刻 t 内）

*   `IY_run  = 𝟙[StateY'==Runaway]`
*   `IY_zero = 𝟙[StateY'==Zero]`
*   `wY      = 0.9·IY_run + 0.25·IY_zero`
*   `sgnY    = {Runaway:+1, Normal:0, Zero:0}[StateY']`（Zeroはvに寄与しない）
*   `boostY  = 1 + 0.35·𝟙[ΔY'==Spike]`

**v の更新（汎用式）**：
`vX'' = clamp( vX' + Σ_{Y≠X} sgnY·wY·k_{Y→X}·g(vY')·boostY , 0, 2 )`

※ `X=C` については **§7.2 の式で置換**する（B→C 項にゲートが掛かるため）。`X∈{A,B}` は本式のまま。

`ΔX'' = max( ΔX', 1·𝟙[StateX'==Runaway], 0.5·𝟙[StateX'==Zero],`
`         0.5·𝟙[∃Y≠X: (k_{Y→X}≠0) ∧ (StateY'∈{Runaway, Zero})] )`

※ 上式の下限引上げは **max** により重ね掛け。**最も強い下限が優先**。

**State の引継ぎ**：`StateX'' = StateX'`（I は State を変更しない。State 変更は §8.0/§8.1、§6.1.1、§11 TR のみ）

**C3高の微調整（任意・連続｜§2.7.1）**：

※ **C3 修飾の適用点はここのみ**（§2.7.3）。TR 前に clamp 済みであること。

### 7.2 E2→C単一化の部分ゲート（連続）— B→C 項のみに適用

vC'' = clamp( vC'
            + (1 - η_gate·gate_E2C) · ( sgnB·wB·k_{B→C}·g(vB')·boostB )   // B→C：ゲート対象
            + ( sgnA·wA·k_{A→C}·g(vA')·boostA )                            // A→C：ゲート非対象

*   ゲートは **B→C 項にのみ**適用する（E2 の直投影 `vC'` と B→C 経路の二重適用を防ぐため）。

*   **A→C 項**：既定 `k_{A→C}=0` のため既定では消える。**`k_{A→C}≠0` を設定した場合は上式の通り無ゲートで加算される**（E2 とは無関係な経路のため）。

## 8. 状態判定（Runaway／Zero）・維持・解除【v3.2.2 で章題変更】

> **v3.2.2 変更**：v3.2.1 まで Runaway の**初期発生源が未定義**だった（TR-2/TR-5 と §6.1.1 は既存の Runaway を前提とする連鎖規則であり、最初の Runaway を立てる規則が存在しなかった）。本章 §8.0 で Zero と対称な判定規則を定義する。

### 8.0 Runaway 判定（v3.2.2 新設）

**対象**：`X ∈ {A,B,C}`。EF チャネル（E0..E3）にも同一規則を適用する
（ただし観測層が `StateE_prop` を供給した場合は提案を優先｜§2.8.4）。

**判定入力**：融合後の `vX_t, ΔX_t`（§2.8｜EF投影前）。

**発火（entry）**——`StateX ≠ Zero` のとき：

*   **即時**：`vX_t ≥ θ_run_hi(=1.6) ∧ ΔX_t ≥ 1.0`
*   **持続**：`(vX_t ≥ 1.5 ∧ ΔX_t ≥ 1.0)` が `run_streak_X ≥ 2`（当該フレームを含む連続成立数）

→ `StateX := Runaway`

**解除（exit）**——`StateX = Runaway` のとき：

*   `vX_t ≤ θ_run_lo(=1.3)` が `calm_streak_X ≥ 2`（2フレーム連続）
    → `StateX := Normal`

**ヒステリシス**：`1.3 < vX_t < 1.6` の帯では現状維持（チャタリング防止）。

**優先関係**：

*   `StateX = Zero` の間は本判定を**スキップ**（Zero の解除は §8.1）。
*   本判定の**後段**で適用される §6.1.1（EF引上げ）・§11（TR）による State 変更は本判定に優先する。
*   A にも適用する（A-Runaway＝過剰駆動。`w_vA=-1` によりスコア上は v が保護的に働くが、
    StateMag=2 と Δ 下限引上げ（§7.1）は通常どおり作用する）。

### 8.1 Zero 判定（Core層の入力契約）

**Core層は観測手段を規定しない。** 観測層は以下を Core に供給する。

| 入力 | 型 | 意味 |
| --- | --- | --- |
| `w_zero_int` | `[0, 5]` の実数 | **内的** Zero 徴候の加重和（自己駆動の停止） |
| `zero_ext_flags` | E0..E3 の bool | **外的** Zero 加点要因の成立（各チャネル） |

**`w_zero_ext` の算出（Core層）**：

```
w_zero_ext = 1.0·𝟙[E0: 体調悪化により駆動不能]
           + 1.0·𝟙[E1: 外界情報遮断]
           + 1.0·𝟙[E2: 社会的断絶／評価データ不能]
           + 1.0·𝟙[E3: ノイズ誘導により入力不能]
```

**Zero 発火（entry）**：

```
(w_zero_int + w_zero_ext) ≥ 3.0  →  StateA := Zero
```

**判定対象**：既定は **A**（Zero＝自己駆動の停止であり、A が担う。TR-1・§12.4・回復監視が
すべて A を参照することと整合）。`zero_target` 設定で拡張可能だが既定は `A` 固定。
B/C の Zero は §6.1.1・TR 経由でのみ発生する。

**Zero 解除（exit）**【v3.2.2 新設——v3.2.1 まで Lock 無し Zero の解除規則が未定義だった】：

```
StateA = Zero ∧ ZeroLock == 0
∧ (w_zero_int + w_zero_ext) ≤ 1.5 が zero_low_streak ≥ 2（2フレーム連続）
∧ EMA_vA(t) > EMA_vA(t-1)
→ StateA := Normal
```

（発火 `≥3.0`／解除 `≤1.5` のヒステリシス。判定は §7.3 手順3 で行う）

**観測層の契約**（詳細は観測層仕様 §4）：

*   `w_zero_int ∈ [0, 5]`、単調（徴候が増えれば非減少）
*   観測窓を明示（例：直近3往復／EMA併用可）
*   各徴候の寄与を監査可能な形で出力（`zero_explain`）
*   対話ドメインの参照実装は**付録A**（重みは v3.2.0 §8.1 と同値）

**EMA（回復監視）**：`EMA_vA(t) = λ·vA''_t + (1-λ)·EMA_vA(t-1)`（`λ∈(0,1]`、初期 `EMA_vA(0)=vA''_0`、更新は §7.3 手順13）

### 8.2 Zero-Lock

8.2.1 **発動**：`w_zero_int ≥ 2.0` **かつ**（`StateE2=Runaway` **または** `w_zero_ext ≥ 2.0`）
8.2.2 **ロック強度**：`ZeroLock ∈ {0,1,2}`（既定 0）。発動時 `ZeroLock := max(ZeroLock, 2)`。
8.2.3 **効果**：`StateX=Zero` 優先保持（Zero-Guard で R1以上）／`ZeroLock>0` の間、Zero からの遷移は抑制（**§8.1 の Zero 解除・TR-2 等のRunaway化も抑制**）

8.2.4 **解除（時間的逓減）**

**基本規則**：**A/B/C の Runaway不在**が **n=2** ステップ継続で `ZeroLock := max(0, ZeroLock-1)`

**回復ブースト（+1段階）**：以下の**いずれか**が成立したフレームでは、逓減を1段階追加する
（すなわち `ZeroLock := max(0, ZeroLock-2)`）。

*   **判定B-1（EMAベース｜既定）**：`EMA_vA(t) > EMA_vA(t-1)` が **2フレーム連続**
*   **判定B-2（内因性増分ベース｜任意）**：`ΔvA_intrinsic > 0` が **2フレーム連続**
    ここで
    `ΔvA_intrinsic(t) := (vA''_t - vA''_{t-1}) - 0.5·(vE1 + vE3)_t - θ_E0·0.5·(vE0)_t`
    （`θ_E0∈[0,1]` 既定 `0.5`）
    ※ EF由来の見かけ上の増分を差し引き、**A の内因性回復のみ**を検出する。

**判定の選択**：`zero_unlock_mode ∈ {ema, intrinsic}`（既定 `ema`）。両者の併用（AND/OR）は行わない。

**EMA λ 推奨値（ZeroLock連動）**：`ZeroLock=2 → λ=0.7`／`1 → 0.6`／`0 → 0.5`

**運用規則（実装）**：
`if ZeroLock>0:` **Zeroを保持**し、**Zero→Runaway/Normal**の遷移と **TR-2** の発火を**抑制**。
他TRは定義通り（Zero優先の上書き原則に従う）。

**実装補足（競合整合）**：

*   TR評価時は **Zero 優先（Zero > Runaway > Normal）** を先に適用。
*   ZeroLock>0 のフレームでは **TR-2 の条件評価をスキップ**。
*   TR-3/4 は数値（ΔやState）に作用するが、**Zero保持中は Zero優先で上書き**。
*   ZeroLock解除判定は **A/B/C の Runaway不在カウント**のみ（EFの状態変化は含めない：§11 TR-6 と整合）。

## 10. 推定と二段判定（一次：言語／二次：裏取り）

### 10.1 一次判定（言語）

*   `B_type / wB`、`C_type / wC` を **§9 の言語シグナル・比較語・参照点**から推定
*   出力は**重心**（`wB`, `wC`）とし、確信度 `conf ∈ [0,1]` を併記
*   しきい：`max(wB) ≥ 0.6` でラベル固定（`B_type` を確定）。同様に `max(wC) ≥ 0.6` で `C_type` を確定
*   未満は `None`（**重心のみ保持**し、ラベルは付けない）

### 10.2 二次判定（裏取り）

**目的**：言語表現は**装われうる**（社会的望ましさ・言語習慣・役割演技）。一次判定を**言語以外の証跡**で検証する。

**裏取りの証跡（いずれか2つ以上の一致で確定）**：

| 種別 | B1（内向き）の予測 | B2（外向き）の予測 |
| --- | --- | --- |
| 参照点 | 過去の自分・自己設定の理想 | 他者・平均・世間 |
| 時制 | 「あのとき」「本来」（自己履歴参照） | 「今」「みんな」（同時代参照） |
| E2 依存 | E2 に**依存しない**評価圧の持続 | E2 上昇時に **vB が連動上昇** |
| 単独時 | 単独でも `vB` 高止まり | 単独時は `vB` 低下 |

**手続き**：

1.  一次判定で `max(wB) ≥ 0.6` → 仮ラベル
2.  上表の証跡を**直近の観測窓**（既定：直近3往復／3フレーム）で照合
3.  **2つ以上一致** → `B_type` 確定、`conf := min(1.0, conf + 0.2)`
4.  **一致1つ以下** → `B_type := None`（重心 `wB` のみ保持）、`conf := conf · 0.5`
5.  **矛盾（反対型の証跡が2つ以上）** → `B_type := None`、`wB := (0.5, 0.5)`、監査に `conflict: true` を記録

**C_type も同様**：`C4`（社会文脈型）と `C3`（監視‐自己意識型）は言語が類似するため、
**E2 連動の有無**（C4 は E2 連動／C3 は E2 非依存で持続）を裏取り証跡とする。

**重要**：二次判定が不成立でも **Core の力学は変化しない**（ラベルは弱修飾にのみ影響し、既定では無効）。
確信度の低いラベルで弱修飾を有効化しないこと（推奨：`conf ≥ 0.6` を弱修飾の有効化条件とする）。

## 11. 簡易・状態遷移ルール（TR-1〜TR-6）

（判定対象：I 適用後の `vX''／ΔX''／StateX''`｜**順番固定**：**TR-1 → TR-2 → TR-3 → TR-4 → TR-5 → TR-6**）

**共通規約**

*   **TR判定は連続値で行う**（帯域ラベルは表示用）。
*   TR の効果は**当該フレームの `X''` を直接更新**し、**同フレームの RuinScore に反映される**（§7.3 手順7→9）。
*   後続 TR は**先行 TR の更新結果を見る**（逐次適用）。ただし §11.7-5 の例外あり。

11.1 **TR-1（Zero誘発：C→A）**
条件：`StateC''=Runaway ∧ ΔC'' ≥ 1.5 ∧ vA'' ≤ 1`
→ **`StateA'' := Zero`**（`cooldown_TR1=1`）

11.2 **TR-2（監視過活動化：B→C）**

**基本条件（base）**：`StateB''=Runaway ∧ StateA''=Zero ∧ ZeroLock==0 ∧ cooldown_TR2==0`

**発火条件**：`base ∧ ( vB'' ≥ 1.6 ∨ base_streak ≥ 2 )`

*   `base_streak`：**基本条件（base）が連続成立したフレーム数**（当該フレームを含む）
    `base` 成立時 `base_streak += 1`、不成立時 `base_streak := 0`
*   → **`StateC'' := Runaway`**（`cooldown_TR2=2`）

※ 意味：`vB''` が高い（≥1.6）なら**即時**発火、そうでなくとも**基本条件が2フレーム続けば**発火する（低強度でも持続すれば監視過活動に至る）。

11.3 **TR-3（安定化：A→B）**
条件：`vA'' ≥ 1.5 ∧ ΔB'' ≥ 0.5`（＝A が High 帯 かつ B が Swing 以上）
→ **`ΔB'' := 1`**（減衰）
**ヒステリシス**：発火 `vA'' ≥ 1.55`、解除 `vA'' ≤ 1.45`、または **基本条件が2フレーム連続成立**で発火可。
※ ラベル帯域（High/Mid）境界 `1.5` とヒステリシス閾値（`1.55/1.45`）は**意図的に一致させていない**（帯域境界上でのチャタリング防止）。

11.4 **TR-4（収束：B→C）**
条件：`vB'' ≥ 1.5 ∧ ΔC'' < 0.5 ∧ ZeroLock==0 ∧ StateB''≠Runaway ∧ cooldown_TR2==0`
→ **`StateC'' := Normal`**

11.5 **TR-5（社会トリガ：E2）**
条件：`γ_social* = 2 ∧ StateE2=Runaway`
→ **`StateB'' := Runaway`**（`cooldown_TR5=1`）
※ ルール順序の都合上、同一フレーム内の TR-2 判定には反映されない（**TR-2 連鎖は次フレームで評価**｜§11.7-5）。

11.6 **TR-6（Δの時間減衰／ヒステリシス）**

条件：`A/B/C 全て Runaway不在` が **m=1** ステップ継続。
効果：**`ΔX'' := max(0, ΔX'' − 1)`（X∈{A,B,C}）**

**作用先と持ち越し（v3.2.2 改訂）**：

*   TR-6 は **当該フレームの `ΔX''` を更新**する（同フレームの RuinScore に反映｜§7.3 手順7→9）。
*   加えて commit（§7.3 手順13）で **内在値にも同じ減衰を適用**する：`ΔX_carry := max(0, ΔX_t − 1)`（§2.8.2）。
    次フレームの観測はこれを**上書きせず、§2.8.3 の max 融合**で統合される
    （観測が静かな限り減衰は持続し、新たな動揺の観測は即時反映される）。

**併用可（連続）**：指数平滑の状態依存 `λ ∈ (0,1]`（既定 `λ=0.5`、ZeroLock=0 のとき小さめ設定可）。
連続版を用いる場合：`ΔX'' := (1-λ)·ΔX''`（離散版 `−1` と**排他**。`tr6_mode ∈ {discrete, smooth}`、既定 `discrete`）

※ `m` カウントは **A/B/C の State（離散）に変化が発生した時点でリセット**。EFの State 変化は含めない。

### 11.7 優先原則（競合時の決定則）

1.  **Zero > Runaway > Normal** を**上書き優先**。
2.  同順位の競合は**ルール順の早い方（TR-1→…）を優先**。
3.  `ZeroLock>0` のときは **Zero を保持**して他ルールの変更を抑制（**TR-2 含む**）。
4.  発火後は各 `cooldown[TR_i]` に従い再発火を抑制（デクリメントは §7.4）。
5.  **TR-5 による `StateB''=Runaway` は、同一フレーム内の TR-2 判定には反映されない**（TR-2 は TR-5 より前に評価されるため。連鎖は次フレーム）。

※ Bサブタイプは TR 条件に非介入

## 12. Zero に対する位置づけと解除

12.1 **Zero は Runaway の対極ではなく別基底**（速度・変動の観測困難）
12.2 **Zero 出現時は R1以上（Zero-Guard）**
12.3 **EF-Zero は内部 Zero を誘導し Zero-Lock 化**
12.4 **解除方針**

*   **E0**：睡眠／休息／栄養／鎮痛・通院など内的負荷を軽減
*   **E1**：休息／時間確保／環境調整
*   **E2**：評価距離化／社会圧一時遮断（`γ_social` 実効低下）
*   **E3**：ノイズ除去／単一タスク化
*   **A の微小行動**で `vA` を **+1 相当**押し上げ（内因性増分の強化）

12.5 **Zero-Lock の時間的逓減**：Runaway 不在継続に応じ段階的に解除（既定 `n=2`｜§8.2.4）
12.6 **Lock 無し Zero の解除**：§8.1（w_zero ヒステリシス ∧ EMA 上昇）

### C.3.1 参照実装による検証で判明した安定性修正（v3.2.2 内で反映済み）

初稿の §2.8.2 は「TR 適用後の `X''` を carry する」としていたが、10フレームの参照実装で
**2つの吸収状態（回復不能モード）** が判明したため、公開前に以下へ修正した：

| 症状 | 原因 | 修正 |
| --- | --- | --- |
| EF 存在下で v が 2.0 に飽和し、Runaway が永久に解除されない | `vX''`（EF投影・相互作用込み）を carry すると外部補正が**毎フレーム複利で蓄積** | carry を**内在値 `vX_t`** に変更（§2.8.2）。投影・相互作用はフレーム局所の再計算とし、時間方向の記憶は離散 State が担う |
| 観測が途絶えると Runaway/高 v が永続 | 内在値に復元力が無かった | 欠測フレームで中立への微緩和 `ρ_core=0.1` を追加（§2.8.3） |
| `c_i=1` の cooldown が実質無効 | 発火フレームの commit で即デクリメントされていた | 発火フレームではデクリメントしない（§7.4） |

### C.4 挙動への影響

*   **単一フレームの計算**：不変（§5〜§7、§11 の数式は無変更）。
*   **複数フレームの挙動**：v3.2.1 では実装者の解釈で分岐していたため「基準となる挙動」が存在しない。
    v3.2.2 が初めて時系列挙動を一意に定義する。
*   **State の入口**：v3.2.1 まで観測入力に依存していた `StateB=Runaway` 等は、v3.2.2 では §8.0 により
    v/Δ から導出される。**観測層は State を供給しなくてよい**（EF の `StateE_prop` を除く）。

### C.5 未解決・要確認事項（v3.2.1 から継続＋新規）

*   §5.5 の非対称閾値（4.4／5.4）の設計意図確認（v3.2.1 付録 B.5 から継続）。
*   §8.0 の Runaway 閾値（1.6／1.5／1.3、Δ≥1.0）は Zero 側との対称性と TR-2 閾値（1.6）との整合から
    導出した**新規提案値**。実データでの較正を要する（観測層仕様 §8 の較正手順を使用）。
*   `λ_v=0.6`（観測優位）は対話ドメイン（1フレーム＝1往復）を想定した既定。高頻度フレーム
    （interval ポリシーで dt が小さい場合）では小さめに設定すること（観測層仕様 §3.4）。
