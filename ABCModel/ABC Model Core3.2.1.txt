## 2. 共通仕様（スカラー・状態・記号）

### 2.1 v（Velocity）

2.1.1 **値域**：離散 `0/1/2`（Low/Mid/High）。**内部は連続 `[0,2]` 許容**
2.1.2 **EF も同様**
2.1.3 **離散帯域**：Low: `v<0.5`／Mid: `0.5≤v<1.5`／High: `v≥1.5`
（丸め：`round_half_up(x)=floor(x+0.5)`）

> **境界規約（v3.2.1で統一）**：帯域は **下端閉・上端開 `[lo, hi)`** とし、v・Δ で共通とする。
> この規約は `round_half_up` と**完全に一致**する（`0.5→1`＝Mid、`1.5→2`＝High）。
> ※ v3.2.0 の「Low: `v≤0.5`」は `round_half_up(0.5)=1`（Mid）と矛盾していたため修正。

### 2.2 Δ（変動）

2.2.1 **値域**：`0/1/2`（Stable/Swing/Spike）。内部連続 `[0,2]`
2.2.2 **帯域**：Stable `Δ<0.5`／Swing `0.5≤Δ<1.5`／Spike `Δ≥1.5`（§2.1.3 と同一規約）

### 2.3 State（状態）

2.3.1 **3値**：`Normal / Runaway / Zero`
2.3.2 **数値化**

*   `StateMagX ∈ {0,1,2}`：Normal→0／Zero→1／Runaway→2
*   `dirX ∈ {+1,0,-1}`：Runaway→+1／Normal→0／Zero→-1
    2.3.3 **相互作用符号**：`sgnX={Runaway:+1, Normal:0, Zero:0}`

### 2.4 丸め関数

*   v/Δ：`round_half_up`
*   R：§5.5 Rバンド丸め

## 2.6 Bサブタイプ（評価方向の分類）

**目的**：Bにおける評価基準の参照方向を保持
Core の v/Δ/State・TR・R には直接介入しない

### 2.6.1 定義

*   `B_type ∈ {B1,B2,None}`（既定=None）
*   `wB=(wB1,wB2)`、`wBi∈[0,1]`、`wB1+wB2=1`

本区分（Bサブタイプ）は、評価の「参照方向（内的／外的）」を保持するための文脈情報であり、
評価エネルギーそのもの（vB）や暴走・停止の判定（State、TR、RuinScore）を規定するものではない。
力学的挙動への影響は、評価更新の揺らぎ方（ΔB）および A→B 減衰係数に対する連続的かつ小幅な修飾に限定する。

### 2.6.2 種類

*   **B1：内向き評価（Internal-Oriented）**
    自己基準・理想・内省・自己採点・自己批判ループ
*   **B2：外向き評価（External-Oriented）**
    他者基準・社会基準・比較・承認志向・対外評価参照

### 2.6.3 運用

*   推定・可視化層で保持
*   TR・State離散・Rラベルには非介入
*   連続値への**弱い修飾のみ許可**（§2.7.2 / §6.1.4）

## 2.7 サブタイプ弱修飾（共通）

**共通原則**

*   すべての修飾は**連続・小幅**であり、**離散状態・TR判定・Rラベルには直接介入しない**。
*   すべての修飾関数は `wC`／`wB` の**線形混合**として定義し、**未設定時は恒等（適用なし）**。
*   各修飾は**適用点が一意**であり、複数箇所での重ね掛けを禁止する（§2.7.3）。

## 3. 相互作用 I（A/B/C）

3.1 **係数**：`k_{Y→X} ∈ {-1,0,+1}`（X≠Y, Y∈{A,B,C}）
3.2 **有効化と重み**

*   Runaway(Y)：**強く有効化**
*   Zero(Y)：**弱く**（主に **Δ の下限引上げ**に寄与／vには寄与しない）
*   `ΔY=Spike`：**影響ブースト**

3.3 **推奨既定**

*   `C→A = -1`（監視過活動は生感を抑制）
*   `B→C = +1`（評価厳格化はメタ監視を強化）
*   `A→B = -1`（生感は評価の揺れを減衰）
*   **未指定の係数は 0（無影響）**

3.4 **重み**：Runaway=**0.9**／Zero=0.25／Normal=0（Zero 符号は中立）
3.5 **v のスケーリング**：`g(v)=g_max·tanh(α_v·v)`（`g_max∈[0.45,0.6]`、`α_v∈[0.6,0.8]`、既定 `g_max=0.5, α_v=0.7`）
3.6 **Spikeブースト**：`boost(Δ)=1 + b_spike·𝟙[Δ=Spike]`（`b_spike∈[0.25,0.4]`、既定 `b_spike=0.35`）
3.7 **Cサブタイプの弱い修飾（任意）**
`C_type` または `wC` による修飾は **§2.7（C\_sub\_mod）** に従う（既定は**無効**）。

※ B_subtype は原則として係数・符号・有効化条件に介入しない。
   ただし A→B の減衰係数に限り、§6.1.4 に定める弱修飾を許可する（**任意・既定無効**）。

## 5. RuinScore（危険度）

**前提**：RuinScore は **TR 適用後の `vX''/ΔX''/StateX''`**（Core）および §6.2（E）を入力。

**成分X別**：

*   `RuinScoreX_base = w_vX·vX + w_ΔX·ΔX + w_sX·StateMagX`
    *   **素の値域**（clamp前）：`X∈{B,C}` は `[0,6]`／**`X=A` は `w_vA=-1` のため `[-2,4]`**
    *   `X∈{E0,E1,E2,E3}` は `[0,6]`（外部重みは全て +1）
*   `φ_soft = β·𝟙[ΔX=Spike ∧ StateX=Runaway] + ζ·𝟙[StateX=Zero]`
*   `RuinScoreX_pre = RuinScoreX_base + φ_soft`
*   **強制境界**（スコア段階のみ適用）：
    *   `ΔX=Spike ∧ StateX=Runaway → RuinScoreX_pre := max(…, 5)`（R2以上）
    *   `StateX=Zero → RuinScoreX_pre := max(…, 3)`（R1以上：Zero-Guard）
*   `RuinScoreX = clamp(RuinScoreX_pre, 0, 6)`
*   `RuinScore_core = max(RuinScoreA, RuinScoreB, RuinScoreC)`
*   `RuinScoreE = max(RuinScoreE0, RuinScoreE1, RuinScoreE2, RuinScoreE3)`
*   `RuinScore = max(RuinScore_core, RuinScoreE)`

> **v3.2.1 修正**：v3.2.0 は全成分に「（0〜6）」と注記していたが、`w_vA=-1` により A 成分の素の値域は `[-2,4]` であり誤りだった。clamp により最終値は `[0,6]` に収まるため挙動上の影響はないが、記述を訂正した。
> **設計上の含意**：A は `vA` が高いほどスコアが下がる（保護的）。ただし `ΔA=Spike ∧ StateA=Runaway` の強制境界は A にも適用され、`vA` の高低に関わらず R2 以上になる。これは意図された挙動である。

5.1 **重みの既定**：`w_vA=-1`、`w_vB=1`、`w_vC=1`／`w_ΔX=w_sX=1`（X∈{A,B,C}）
5.2 **推奨初期値**：本番 `β=0, ζ=0`／分析可視化 `β=0.5, ζ=0.5`
5.3 **手順（順序厳守）**

1.  Core各成分の基本和（`X''` を入力） → `RuinScoreX_base → φ_soft → RuinScoreX_pre`
2.  成分別の強制境界適用（`max(…, 5/3)`）
3.  成分別 `clamp(0,6)`
4.  Core統合：`RuinScore_core = max(A,B,C)`
5.  外部要素（§6.2）→ `RuinScoreE`
6.  CoreとEの最大：`RuinScore = max(R_core, R_E)`
7.  **二峰性の補足（任意）**（§6.4）
8.  終端強制境界再適用（maxのみ｜冪等）
9.  最終 `clamp(0,6)` → **`R_cont` を確定・保存**（§5.5.1）→ 整数化（Rバンド丸め）

5.4 **Rレベル**：R0=0–2／R1=3–4／R2=5／R3=6
5.5 **丸め（Rバンド）**：
`R_cont`（§5.3 手順9 時点の連続値）に対し、

*   **R0帯**：`R_cont < 2.5 → 2`
*   **R1帯**：`2.5 ≤ R_cont < 4.4 → 4`
*   **R2帯**：`4.4 ≤ R_cont < 5.4 → 5`
*   **R3帯**：`R_cont ≥ 5.4 → 6`

> **閾値の非対称性について（v3.2.1で明文化）**：R1→R2 境界は `4.5` ではなく **`4.4`**、R2→R3 境界は `5.5` ではなく **`5.4`** とする。これは四捨五入ではなく、**上位帯へわずかに入りやすくする（安全側＝過検知側に倒す）意図的な非対称設定**である。R0/R1 境界のみ `2.5`（中点）を用いる。
> ※ この解釈は数値配置からの推定を含む。設計意図と異なる場合は本注記を修正のこと。

### 5.5.1 R_cont の保持（必須）

Rバンド丸めは**代表値への写像であり情報を失う**（例：`R_cont=0.0` も `R_cont=2.4` も同じく `R=2`）。
そのため **`R_cont` を監査フィールドに必ず保存する**（§5.7 / §14）。
低リスク域（R0帯）の推移追跡・時系列可視化・閾値チューニングは `R` ではなく **`R_cont` を用いること**。

5.6 **強制境界**：`Spike×Runaway ⇒ ≥5`／`Zero ⇒ ≥3`
5.7 **監査フィールド（例）**：

```
r_explain = {
  top_source: "A|B|C|E0|E1|E2|E3",
  forced: ["ZeroGuard" | "SpikeRunaway" | ...],   // 空配列可
  r_cont: <float>,        // §5.5.1（必須）
  r_band: 2|4|5|6,        // Rバンド丸め後
  r_level: "R0|R1|R2|R3",
  blend_used: bool,
  soft_used: bool
}
```

> **v3.2.1 修正**：v3.2.0 の例示にあった空要素 `[ ]`（迷子のトークン）を除去し、`r_cont`／`r_band`／`r_level` を明示フィールド化。

※ `B_type / wB` は RuinScore に直接介入しない

## 6. EF→Core 投影（外部補正）

### 6.1 成分別投影（連続内部）

**適用順**：(a) 連続式 → (b) サブタイプ弱修飾（§2.7.2 / §2.7.1 の `δ_C2`）→ (c) clamp

**(a) 連続式**

*   `adjE2   = min(2, vE2 + (γ_social* - 1))`（§4.3 を用いる。未使用時は `γ_social* = γ_social`）
*   `vA'     = vA - 0.5·(vE1 + vE3 + vE0)`
*   `vB'     = vB + max( 0.5·adjE2, 0.5·vE3 )`
*   `vC'     = vC + max( 0.5·adjE2, 0.5·vE3, 0.5·vE0 )`
*   `ΔA'     = max(ΔA, ΔE1, ΔE3, ΔE0)`
*   `ΔB'     = max(ΔB, ΔE2, ΔE3)`
*   `ΔC'     = min( 2, max(ΔC, ΔE2, ΔE3, ΔE0) + κ_socialC · 𝟙[adjE2 = 2] )`
*   `StateX' = StateX`

**E2→C経路の単一化**（過重積防止／単調性保証｜B→C項の連続ゲート）

*   `gate_E2C = adjE2 / 2`（adjE2=0→0, 1→0.5, 2→1.0）
*   `η_gate = 1.0`（adjE2=0→抑制0、=1→約50%抑制、=2→完全遮断）
*   ※ ゲートは **§7.2 の B→C 項にのみ**適用する（適用点は §7.2）。

**(b) サブタイプ弱修飾（任意・§2.7.3 の適用点に従う）**

*   `ΔB' := ΔB' + δ_B1(wB1) + δ_B2(wB2)`（§2.7.2）
*   `ΔC' := ΔC' + δ_C2(wC2)`（§2.7.1）

**(c) clamp（I 適用前の数域保証）**

*   `vA', vB', vC', ΔA', ΔB', ΔC' := clamp(…, 0, 2)`

> **v3.2.1 修正**：v3.2.0 は本節末尾に `k_{A→B} := k_{A→B}·(1-0.2·wB1)` を**無条件の投影式として記載**する一方、§6.1.4 では**同式を「必要に応じて適用してよい」任意規則**として重複記載しており、無条件適用か任意かで挙動が割れる矛盾があった。**本節からは削除し、§6.1.4（任意・既定無効）に一本化**した。

6.1.1 **外的Runawayによる内部引上げ（明示規則）**

*   `if (StateE1==Runaway) and (vA' ≥ 1): StateA' := Runaway`
*   `if (StateE3==Runaway) and (ΔC'==Spike): StateC' := Runaway`
*   `if (StateE0==Runaway) and (vA' ≤ 1): StateA' := Zero`
*   `if (StateE0==Runaway) and (ΔC'==Spike): StateC' := Runaway`

※ 判定に用いる `vA'/ΔC'` は **§6.1(c) の clamp 後**の値とする。

6.1.2 **外的状態更新の競合決定則**
**Zero ＞ Runaway ＞ Normal** を適用。
同一フレーム内で複数候補が出た場合はこの優先度で単一の `StateX'` に正規化。
※ 中圧域（adjE2≈1）では直投影（`vC'`）と B→C 経路が同時寄与。
高圧（adjE2=2）では B→C 経路が完全遮断（直投影と二重適用しない）。

6.1.3 **Cサブタイプの弱い関与（任意）**
`wC` に基づく微調整は **§2.7（C\_sub\_mod）** に従う（連続小幅・clamp 前提）。

6.1.4 **Bサブタイプの弱い関与（任意・既定無効）**

`wB` に基づく ΔB の微調整は §2.7.2（B_sub_mod）に従う（§6.1(b) で適用）。

加えて、**B1 高では A→B の減衰を弱める**修飾を**任意で**適用してよい（**既定は無効**）。

*   `k_{A→B} := k_{A→B} · (1 - 0.2·wB1)`
*   **適用点**：I 適用前（§7.1 で `k_{A→B}` を参照する前）。**1フレームにつき1回のみ**。
*   **有効化**：`B_sub_mod = enabled` かつ `wB` 設定時のみ。未設定・無効時は恒等（修飾なし）。

※ 連続小幅・clamp 前提
※ TR・State離散・Rラベルには直接介入しない

### 6.2 外的 RuinScore（要素別→統合）

*   `RuinScoreE0 = w_vE0·vE0 + w_ΔE0·ΔE0 + w_sE0·StateMagE0`

### 6.3 統合

`RuinScore_core = max(RuinScoreA, RuinScoreB, RuinScoreC)`
`RuinScore = max(RuinScore_core, RuinScoreE)`

### 6.4 二峰性の補足（任意）

*   **従来ブレンド**：
    `secMax = second_max(RuinScoreA, RuinScoreB, RuinScoreC)`

## 7. 相互作用の適用順序と更新

### 7.1 I 適用（EF重畳後の vX'/ΔX'/StateX'｜同一時刻 t 内）

*   `IY_run  = 𝟙[StateY'==Runaway]`
*   `IY_zero = 𝟙[StateY'==Zero]`
*   `wY      = 0.9·IY_run + 0.25·IY_zero`
*   `sgnY    = {Runaway:+1, Normal:0, Zero:0}[StateY']`（Zeroはvに寄与しない）
*   `boostY  = 1 + 0.35·𝟙[ΔY'==Spike]`
*   `g(v)    = g_max · tanh(α_v · v)`（既定: `g_max=0.5, α_v=0.7`）

**v の更新（汎用式）**：
`vX'' = clamp( vX' + Σ_{Y≠X} sgnY·wY·k_{Y→X}·g(vY')·boostY , 0, 2 )`

※ `X=C` については **§7.2 の式で置換**する（B→C 項にゲートが掛かるため）。`X∈{A,B}` は本式のまま。

**Δ の下限引上げ**（関係組に限定：`k_{Y→X}≠0`）：
`ΔX'' = max( ΔX', 1·𝟙[StateX'==Runaway], 0.5·𝟙[StateX'==Zero],`
`         0.5·𝟙[∃Y≠X: (k_{Y→X}≠0) ∧ (StateY'∈{Runaway, Zero})] )`

※ 上式の下限引上げは **max** により重ね掛け。**最も強い下限が優先**。

**State の引継ぎ**：`StateX'' = StateX'`（I は State を変更しない。State 変更は §6.1.1 と §11 TR のみ）

**C3高の微調整（任意・連続｜§2.7.1）**：
`ΔC'' := clamp( ΔC'' + δ_C3(wC3), 0, 2 )`
※ **C3 修飾の適用点はここのみ**（§2.7.3）。TR 前に clamp 済みであること。

### 7.2 E2→C単一化の部分ゲート（連続）— B→C 項のみに適用

**Cの v 更新は以下で §7.1 の汎用式を置換（上書き）**：

```
vC'' = clamp( vC'
            + (1 - η_gate·gate_E2C) · ( sgnB·wB·k_{B→C}·g(vB')·boostB )   // B→C：ゲート対象
            + ( sgnA·wA·k_{A→C}·g(vA')·boostA )                            // A→C：ゲート非対象
            , 0, 2 )
```

*   ゲートは **B→C 項にのみ**適用する（E2 の直投影 `vC'` と B→C 経路の二重適用を防ぐため）。
*   `adjE2=0→無抑制`, `=1→約50%抑制`, `=2→完全遮断`。
*   **A→C 項**：既定 `k_{A→C}=0` のため既定では消える。**`k_{A→C}≠0` を設定した場合は上式の通り無ゲートで加算される**（E2 とは無関係な経路のため）。

> **v3.2.1 修正**：v3.2.0 の置換式は B→C 項のみを持ち「A→Cは未定義=0」と固定していたため、利用者が `k_{A→C}≠0` を設定しても §7.2 の上書きで**黙って無視される**拡張性の欠陥があった。A→C 項を明示的に含め、ゲート対象外であることを規定した。

### 7.3 処理パイプライン（固定順）

1.  観測層から Core 入力を受領（`vX, ΔX, StateX, w_zero_int, w_zero_ext`｜§8.1）

8.  （任意）二峰性の補足（§6.4）
9.  終端強制境界再適用（maxのみ） → 最終clamp → **`R_cont` 保存** → 整数化（Rバンド丸め）

## 8. Zero 判定・維持・解除

### 8.1 Zero 判定（Core層の入力契約）

**Core層は観測手段を規定しない。** 観測層は以下の2値を Core に供給する。

| 入力 | 型 | 意味 |
| --- | --- | --- |
| `w_zero_int` | `[0, 5]` の実数 | **内的** Zero 徴候の加重和（自己駆動の停止） |
| `w_zero_ext` | `[0, 4]` の実数 | **外的** Zero 加点の合計（E0/E1/E2/E3 各1.0上限） |

**Zero確定（Core層の判定）**：

```
Zero確定: (w_zero_int + w_zero_ext) ≥ 3.0
```

**`w_zero_ext` の規定（Core層）**：EF由来のため Core で定義する。

```
w_zero_ext = 1.0·𝟙[E0: 体調悪化により駆動不能]
           + 1.0·𝟙[E1: 外界情報遮断]
           + 1.0·𝟙[E2: 社会的断絶／評価データ不能]
           + 1.0·𝟙[E3: ノイズ誘導により入力不能]
```

**`w_zero_int` の規定（観測層に委譲）**：
内的徴候の観測方法は**ドメイン依存**であるため、Core層は値域と意味のみを規定する。
**対話ドメインにおける参照実装は付録A**を参照（v3.2.0 §8.1 の4条件はここへ移設）。

観測層は以下の**契約**を満たすこと：

*   `w_zero_int ∈ [0, 5]`、単調（徴候が増えれば非減少）
*   観測窓を明示（例：直近3往復／EMA併用可）
*   各徴候の寄与を監査可能な形で出力（`zero_explain`）

> **v3.2.1 修正**：v3.2.0 §8.1 は「次の一言の連続不成立」「強制三択の無回答」等、**対話エージェント固有の観測量を Core層に直接記載**しており、レイヤー分離（§1.5）に違反していた。Core層は入力契約のみとし、対話ドメイン実装を付録Aへ分離した。**数値挙動は同一**（付録Aの重みは v3.2.0 と同値）。

**EMA（参考）**：`EMA_vA(t) = λ·vA''_t + (1-λ)·EMA_vA(t-1)`（`λ∈(0,1]`、初期 `EMA_vA(0)=vA''_0`）

### 8.2 Zero-Lock

8.2.1 **発動**：`w_zero_int ≥ 2.0` **かつ**（`StateE2=Runaway` **または** `w_zero_ext ≥ 2.0`）
8.2.2 **ロック強度**：`ZeroLock ∈ {0,1,2}`（既定 0）。発動時 `ZeroLock := max(ZeroLock, 2)`。
8.2.3 **効果**：`StateX=Zero` 優先保持（Zero-Guard で R1以上）／`ZeroLock>0` の間、Zero からの遷移は抑制（**TR-2 等のRunaway化も抑制**）

8.2.4 **解除（時間的逓減）**

**基本規則**：**A/B/C の Runaway不在**が **n=2** ステップ継続で `ZeroLock := max(0, ZeroLock-1)`

**回復ブースト（+1段階）**：以下の**いずれか**が成立したフレームでは、逓減を1段階追加する
（すなわち `ZeroLock := max(0, ZeroLock-2)`）。

*   **判定B-1（EMAベース｜既定）**：`EMA_vA(t) > EMA_vA(t-1)` が **2フレーム連続**
*   **判定B-2（内因性増分ベース｜任意）**：`ΔvA_intrinsic > 0` が **2フレーム連続**
    ここで
    `ΔvA_intrinsic(t) := (vA''_t - vA''_{t-1}) - 0.5·(vE1 + vE3)_t - θ_E0·0.5·(vE0)_t`
    （`θ_E0∈[0,1]` 既定 `0.5`）
    ※ EF由来の見かけ上の増分を差し引き、**A の内因性回復のみ**を検出する。

**判定の選択**：`zero_unlock_mode ∈ {ema, intrinsic}`（既定 `ema`）。両者の併用（AND/OR）は行わない。

> **v3.2.1 修正**：v3.2.0 は `ΔvA_intrinsic` の式を「微増例」として提示しながら、**どの条件にも使われず宙に浮いていた**（実際の条件は EMA のみ）。判定B-2として正式な選択肢に格上げし、`zero_unlock_mode` で選択する形に整理した。既定は v3.2.0 と同じ EMA 判定。

**EMA λ 推奨値（ZeroLock連動）**：`ZeroLock=2 → λ=0.7`／`1 → 0.6`／`0 → 0.5`

**運用規則（実装）**：
`if ZeroLock>0:` **Zeroを保持**し、**Zero→Runaway/Normal**の遷移と **TR-2** の発火を**抑制**。
他TRは定義通り（Zero優先の上書き原則に従う）。

**実装補足（競合整合）**：

*   TR評価時は **Zero 優先（Zero > Runaway > Normal）** を先に適用。
*   ZeroLock>0 のフレームでは **TR-2 の条件評価をスキップ**。
*   TR-3/4 は数値（ΔやState）に作用するが、**Zero保持中は Zero優先で上書き**。
*   ZeroLock解除判定は **A/B/C の Runaway不在カウント**のみ（EFの状態変化は含めない：§11 TR-6 と整合）。

## 10. 推定と二段判定（一次：言語／二次：裏取り）

### 10.1 一次判定（言語）

*   `B_type / wB`、`C_type / wC` を **§9 の言語シグナル・比較語・参照点**から推定
*   出力は**重心**（`wB`, `wC`）とし、確信度 `conf ∈ [0,1]` を併記
*   しきい：`max(wB) ≥ 0.6` でラベル固定（`B_type` を確定）。同様に `max(wC) ≥ 0.6` で `C_type` を確定
*   未満は `None`（**重心のみ保持**し、ラベルは付けない）

### 10.2 二次判定（裏取り）

**目的**：言語表現は**装われうる**（社会的望ましさ・言語習慣・役割演技）。一次判定を**言語以外の証跡**で検証する。

**裏取りの証跡（いずれか2つ以上の一致で確定）**：

| 種別 | B1（内向き）の予測 | B2（外向き）の予測 |
| --- | --- | --- |
| 参照点 | 過去の自分・自己設定の理想 | 他者・平均・世間 |
| 時制 | 「あのとき」「本来」（自己履歴参照） | 「今」「みんな」（同時代参照） |
| E2 依存 | E2 に**依存しない**評価圧の持続 | E2 上昇時に **vB が連動上昇** |
| 単独時 | 単独でも `vB` 高止まり | 単独時は `vB` 低下 |

**手続き**：

1.  一次判定で `max(wB) ≥ 0.6` → 仮ラベル
2.  上表の証跡を**直近の観測窓**（既定：直近3往復／3フレーム）で照合
3.  **2つ以上一致** → `B_type` 確定、`conf := min(1.0, conf + 0.2)`
4.  **一致1つ以下** → `B_type := None`（重心 `wB` のみ保持）、`conf := conf · 0.5`
5.  **矛盾（反対型の証跡が2つ以上）** → `B_type := None`、`wB := (0.5, 0.5)`、監査に `conflict: true` を記録

**C_type も同様**：`C4`（社会文脈型）と `C3`（監視‐自己意識型）は言語が類似するため、
**E2 連動の有無**（C4 は E2 連動／C3 は E2 非依存で持続）を裏取り証跡とする。

**重要**：二次判定が不成立でも **Core の力学は変化しない**（ラベルは弱修飾にのみ影響し、既定では無効）。
確信度の低いラベルで弱修飾を有効化しないこと（推奨：`conf ≥ 0.6` を弱修飾の有効化条件とする）。

> **v3.2.1 追加**：v3.2.0 の §10 は章題で「二段判定（一次：言語／二次：裏取り）」を掲げながら、**本文に二次（裏取り）の記述が存在しなかった**。本節で補完した。

## 11. 簡易・状態遷移ルール（TR-1〜TR-6）

（判定対象：I 適用後の `vX''／ΔX''／StateX''`｜**順番固定**：**TR-1 → TR-2 → TR-3 → TR-4 → TR-5 → TR-6**）

**共通規約**

*   **TR判定は連続値で行う**（帯域ラベルは表示用）。
*   TR の効果は**当該フレームの `X''` を直接更新**し、**同フレームの RuinScore に反映される**（§7.3 手順5→7）。
*   後続 TR は**先行 TR の更新結果を見る**（逐次適用）。ただし §11.7-5 の例外あり。

11.1 **TR-1（Zero誘発：C→A）**
条件：`StateC''=Runaway ∧ ΔC'' ≥ 1.5 ∧ vA'' ≤ 1`
→ **`StateA'' := Zero`**（`cooldown_TR1=1`）

11.2 **TR-2（監視過活動化：B→C）**

**基本条件（base）**：`StateB''=Runaway ∧ StateA''=Zero ∧ ZeroLock==0 ∧ cooldown_TR2==0`

**発火条件**：`base ∧ ( vB'' ≥ 1.6 ∨ base_streak ≥ 2 )`

*   `base_streak`：**基本条件（base）が連続成立したフレーム数**（当該フレームを含む）
    `base` 成立時 `base_streak += 1`、不成立時 `base_streak := 0`
*   → **`StateC'' := Runaway`**（`cooldown_TR2=2`）

> **v3.2.1 修正**：v3.2.0 の「`vB'' ≥ 1.6` または **2フレーム連続**」は、**何が2フレーム連続なのか**（基本条件全体か／`vB''≥1.6` か／別の量か）が未定義で、実装者により解釈が分岐した。**基本条件 base の連続成立フレーム数 `base_streak`** として明示定義した。
> ※ 意味：`vB''` が高い（≥1.6）なら**即時**発火、そうでなくとも**基本条件が2フレーム続けば**発火する（低強度でも持続すれば監視過活動に至る）。

11.3 **TR-3（安定化：A→B）**
条件：`vA'' ≥ 1.5 ∧ ΔB'' ≥ 0.5`（＝A が High 帯 かつ B が Swing 以上）
→ **`ΔB'' := 1`**（減衰）
**ヒステリシス**：発火 `vA'' ≥ 1.55`、解除 `vA'' ≤ 1.45`、または **基本条件が2フレーム連続成立**で発火可。
※ ラベル帯域（High/Mid）境界 `1.5` とヒステリシス閾値（`1.55/1.45`）は**意図的に一致させていない**（帯域境界上でのチャタリング防止）。

> **v3.2.1 修正**：v3.2.0 の「`vA''=High(=2, v≥1.5)`」は、離散値 `=2` と連続閾値 `≥1.5` の併記で紛らわしかった。**連続値条件 `vA'' ≥ 1.5`** に統一（挙動は同一）。`ΔB''=Swing(Δ≥0.5)` も同様に `ΔB'' ≥ 0.5` へ統一。

11.4 **TR-4（収束：B→C）**
条件：`vB'' ≥ 1.5 ∧ ΔC'' < 0.5 ∧ ZeroLock==0 ∧ StateB''≠Runaway ∧ cooldown_TR2==0`
→ **`StateC'' := Normal`**

11.5 **TR-5（社会トリガ：E2）**
条件：`γ_social* = 2 ∧ StateE2=Runaway`
→ **`StateB'' := Runaway`**（`cooldown_TR5=1`）
※ ルール順序の都合上、同一フレーム内の TR-2 判定には反映されない（**TR-2 連鎖は次フレームで評価**｜§11.7-5）。

11.6 **TR-6（Δの時間減衰／ヒステリシス）**

条件：`A/B/C 全て Runaway不在` が **m=1** ステップ継続。
効果：**`ΔX'' := max(0, ΔX'' − 1)`（X∈{A,B,C}）**

**作用先の明示（v3.2.1）**：

*   TR-6 は **当該フレームの `ΔX''` を更新**する。
*   したがって **同フレームの RuinScore に反映される**（§7.3 手順5→7）。
*   更新後の `ΔX''` が次フレームの `ΔX` の初期値となる（持ち越し）。

**併用可（連続）**：指数平滑の状態依存 `λ ∈ (0,1]`（既定 `λ=0.5`、ZeroLock=0 のとき小さめ設定可）。
連続版を用いる場合：`ΔX'' := (1-λ)·ΔX''`（離散版 `−1` と**排他**。`tr6_mode ∈ {discrete, smooth}`、既定 `discrete`）

※ `m` カウントは **A/B/C の State（離散）に変化が発生した時点でリセット**。EFの State 変化は含めない。

> **v3.2.1 修正**：v3.2.0 は `ΔX := max(0, ΔX − 1)` の作用先（当該フレームの `Δ''` か／次フレームへの持ち越し状態か）が不明で、**同フレームの RuinScore に影響するか否か**で結果が分岐した。当該フレームの `ΔX''` を更新し同フレームのスコアに反映されると明示。また離散版と連続版の関係（排他）を規定した。

### 11.7 優先原則（競合時の決定則）

1.  **Zero > Runaway > Normal** を**上書き優先**。
2.  同順位の競合は**ルール順の早い方（TR-1→…）を優先**。
3.  `ZeroLock>0` のときは **Zero を保持**して他ルールの変更を抑制（**TR-2 含む**）。
4.  発火後は各 `cooldown[TR_i]` に従い再発火を抑制（デクリメントは §7.4）。
5.  **TR-5 による `StateB''=Runaway` は、同一フレーム内の TR-2 判定には反映されない**（TR-2 は TR-5 より前に評価されるため。連鎖は次フレーム）。

※ Bサブタイプは TR 条件に非介入

## 12. Zero に対する位置づけと解除

12.1 **Zero は Runaway の対極ではなく別基底**（速度・変動の観測困難）
12.2 **Zero 出現時は R1以上（Zero-Guard）**
12.3 **EF-Zero は内部 Zero を誘導し Zero-Lock 化**
12.4 **解除方針**

*   **E0**：睡眠／休息／栄養／鎮痛・通院など内的負荷を軽減
*   **E1**：休息／時間確保／環境調整
*   **E2**：評価距離化／社会圧一時遮断（`γ_social` 実効低下）
*   **E3**：ノイズ除去／単一タスク化
*   **A の微小行動**で `vA` を **+1 相当**押し上げ（内因性増分の強化）

12.5 **Zero-Lock の時間的逓減**：Runaway 不在継続に応じ段階的に解除（既定 `n=2`｜§8.2.4）
