# 制約下動的状態遷移システム（UCD-F）汎用設計書 — Universal Core v2.0.0

> **本書の位置づけ**
> v1.0.0 系の3設計書（`UCD-F`, `UCD-F_ABC`, `Py_UCD-F_ABC`）を検証し、
> 「特定の実行環境・ドメインに依存しない**抽象コア**」と「差し替え可能な**プロファイル**」に
> 層分離して再構築した汎用版である。
> 既存の WebGPU / WGSL / WebRTC / ABC-32bit パッキング等は、本書では
> *コアの規範ではなく* **参照プロファイル（Reference Profile）** として位置づける。

---

## 0. 検証所見（v1.0.0 からの再構築理由）

| # | v1.0.0 系の課題 | v2.0.0 の対応 |
| --- | --- | --- |
| 1 | 形式モデルが版ごとに不整合（`UCD-F`=12要素 `(S,A,C,B,D,M,Q,ε,V,P,H,L)` ／ `UCD-F_ABC`=10要素 `(S,A,C,B,D,M,ε,V,T,N)` ／ `Py_UCD-F_ABC`=11要素 `(U,S,A,C,B,D,M,ε,V,T,N)`）。核タプルが安定しない。 | **不変な7要素の抽象コア**を確定し、他は「能力（Capability）」として分離（§2）。 |
| 2 | 「Universal」を名乗るが WebGPU/WGSL/WebRTC/32bit-ABC が本文に直書きされ、非対応環境で破綻。 | 実装技術をすべて**実行プロファイル**へ退避（§7）。コアは技術中立。 |
| 3 | 抽象設計・計算バックエンド・転送・ドメインモデルが同一階層で混在。 | **4層アーキテクチャ**（抽象コア／機構契約／実行プロファイル／ドメインプロファイル）へ整理（§1）。 |
| 4 | 「魂のビットパッキング」「Schrödinger's Culling」「運命の調律」等、比喩が規範文と混線。 | 規範用語を中立化し、比喩は *別名（俗称）* として括弧内に併記のみ許容。 |
| 5 | 必須／任意の区別、モジュール間の契約が未定義。 | **適合性レベル（Core / Standard / Full）**と各機構の**インターフェース契約**を定義（§9）。 |
| 6 | ABC/VIF という心理力学モデルがコアに埋め込まれ、他ドメインへ転用不能。 | VIF を**汎用 Dynamics 契約**の一実装、ABC を**参照ドメインプロファイル**へ格下げ（§6, §8）。 |

本書における要求水準は RFC 2119 に準じ、**MUST（必須）／SHOULD（推奨）／MAY（任意）** で表記する。

## 1. アーキテクチャ全体像（4層モデル）

UCD-F は「厳しい資源制約を、決定論・データ指向・段階的詳細度によって技術的優位へ転換する」ためのフレームワークである。汎用性を担保するため、責務を次の4層に分離する。

```
┌─────────────────────────────────────────────────────────┐
│ L4  ドメインプロファイル (Domain Profile)                 │  例: ABC/VIF, 粒子, 群衆, 経済…
│     状態スキーマ・遷移規則・Dynamicsの意味付け             │  （差し替え可能）
├─────────────────────────────────────────────────────────┤
│ L3  実行プロファイル (Execution Profile)                  │  例: WebGPU, Python/wgpu, CPU参照
│     具体的な計算/描画/転送バックエンドへの束縛             │  （差し替え可能）
├─────────────────────────────────────────────────────────┤
│ L2  機構契約 (Mechanism Contracts)                        │  メモリ/空間索引/スケジューラ/履歴/
│     能力ごとの抽象インターフェース                         │  出力/予測/ネットワーク（抽象）
├─────────────────────────────────────────────────────────┤
│ L1  抽象コア (Abstract Core)                              │  不変の形式モデルと状態遷移の意味論
│     形式モデル・決定論・状態遷移の意味論                   │  （規範・不変）
└─────────────────────────────────────────────────────────┘
```

**設計原則（Invariants — 全プロファイルが MUST で満たす）**

1. **決定論優先（Determinism-First）**: 同一の初期シードと同一の入力列からは、いかなる準拠実装でもビット等価な状態列が得られること。
2. **データ指向（Data-Oriented）**: 状態は識別可能なフィールド集合として表現され、実装は SoA/AoS/ビットパックのいずれを選んでもよいが、論理スキーマは実装から独立して定義されること。
3. **段階的詳細度（Graceful Degradation / LOD）**: 資源負荷に応じ精度・更新頻度・実体化度を動的に落としてもコアの意味論を破壊しないこと。**確定状態に影響する適応（シミュレーションLOD）は、確定状態・権威化エントロピーの決定論的関数からのみ導出し、実行時計測（wall-clock・CPU温度・実測フレーム時間等）に依存してはならない MUST NOT**。表示のみの適応（プレゼンテーションLOD）はこの限りでない MAY（§4.1）。
4. **明示的制約（Explicit Constraints）**: メモリ・権限・計算資源の制約は暗黙に踏み越えず、モデルの一級要素 `C` として扱うこと。
5. **可逆性（Reversibility）**: 任意の確定済み時点へ、記録された入力列から再計算のみで到達できること（全状態の逐次保存を要求しない）。

## 2. 抽象コア形式モデル（L1・不変）

### 2.1 核タプル

準拠システムは、次の**7要素の核**を MUST で備える。

$$\text{Core} = (S,\; A,\; C,\; B,\; D,\; M,\; \varepsilon)$$

| 要素 | 名称 | 意味（技術中立） |
| --- | --- | --- |
| $S$ | State（状態） | 各エンティティの論理状態。フィールド集合として定義される固定スキーマ、または非実体領域の要約分布。 |
| $A$ | Action（入力） | 状態を変化させ得る外部入力の列。ユーザー入力・権威化エントロピー・ネットワーク入力を含む。 |
| $C$ | Constraint & Core（制約と遷移中核） | 資源・権限の制約集合と、それを尊重する状態遷移規則（TR: Transition Rule）。 |
| $B$ | Bank（可視性・露出制御） | 権限と観測状態に応じ、どの状態がどの観測者へ露出されるかを規定。 |
| $D$ | Dynamics（力学） | 状態変化に付与される動的性質（慣性・強度・蓄積など）を定義する契約。 |
| $M$ | Metrics（計測） | 負荷・品質指標。**表示適応の入力源**。確定状態に影響する適応の判断には、実行時計測ではなく確定状態由来の指標のみを用いる（§1 原則3）。 |
| $\varepsilon$ | Environment（環境） | 実行環境の制約係数と、外部から収穫される現実ノイズ。 |

### 2.2 状態遷移の意味論

$$S_{t+1} = C\big(S_t,\; A_t,\; D,\; \varepsilon_t\big)$$

- $C$ は**純粋関数**である MUST。同一入力から同一出力を返し、副作用（I/O・描画・乱数の暗黙参照）を持たない。
- 乱数が必要な場合、$\varepsilon_t$ に含まれる**明示シード**からの決定論的擬似乱数（例: PCG系ハッシュ）のみを用いる MUST。
- 時間は離散 **Tick**（整数 ID）で進む。全観測者・全ノードは同一 Tick ID で同一の $C$ を適用する MUST。
- $B$（露出制御）と $M$（計測）は遷移式に現れない。**Bank は確定状態を変えず、観測者ごとの露出のみを制御する** MUST。Metrics も確定状態へ影響する判断の入力にしてはならない（§1 原則3）。

### 2.3 能力（Capabilities）— 核の外側

v1.0.0 で核タプルに混在していた要素は、**任意能力**として核から分離する。準拠実装は必要なものだけを実装してよい MAY。

| 能力 | 記号 | 対応する機構契約(§4) | 旧版での扱い |
| --- | --- | --- | --- |
| Quantization / LOD | $Q$ | §4.1 | 核要素だったが実体は Dynamics/Metrics 従属の機構 |
| View / Output | $V$ | §4.5 | 核要素。出力は副作用でありコア外が適切 |
| Prediction | $P$ | §4.6 | 核要素。探索は本番タイムライン外の任意能力 |
| Hierarchy | $H$ | §4.2 | 状態スキーマの一制約として機構へ |
| Layout Schema | $L$ | §4.1 | メモリ機構の内部関心事 |
| Time Dilation | $T$ | §4.3 | スケジューラ機構の一戦略 |
| Network | $N$ | §4.7 | 転送は任意拡張 |

これにより核は版によらず不変となり、旧3版（`UCD-F` / `UCD-F_ABC` / `Py_UCD-F_ABC`）の形式不整合を解消する。

## 3. 論理状態スキーマ（L1↔L2 境界）

### 3.1 スキーマ・ファースト

状態 $S$ は、**論理スキーマ**として実装から独立に定義される MUST。スキーマは以下を宣言する。

- フィールド名、論理型（列挙・整数・固定小数点・正規化実数 等）、値域、意味。
- どのフィールドが**遷移で不可逆に増加するか**（蓄積型 / fatigue 的性質の一般化）。
- どのフィールドが**LOD で精度を落としてよいか**（可縮フィールド）。

物理的表現（ビット幅・パッキング・SoA/AoS・GPU/CPU 常駐）は**実行プロファイルの裁量**である。旧版の「32bit ABC パッキング」は、この論理スキーマの一具体化（§8 参照プロファイル）にすぎない。

### 3.2 スキーマ・コンパイラ契約

実装は、論理スキーマからメモリレイアウトとアクセサ（パック／アンパック）を生成する仕組みを備える SHOULD。生成物は次を保証する MUST。

- アクセサはラウンドトリップ等価（unpack∘pack = 恒等）。
- LOD 段階間の変換（例: 低精度↔高精度プロモーション）が明示的で決定論的。

## 4. 機構契約（L2・抽象インターフェース）

各機構は**抽象契約**として定義し、実装は実行プロファイルで束縛する。ここでは具体技術（WGSL/Morton/WebRTC 等）を規定せず、**満たすべき性質**のみを述べる。

### 4.1 メモリ & 量子化（Memory / Quantization）

- 契約: 論理スキーマに対する読み書きを提供し、GC/アロケーションのフレーム内スパイクを回避する（固定容量プールを推奨 SHOULD）。
- **LOD**: 演算・通信・実体化の精度を動的に段階制御する。段階遷移はコア意味論を保存する MUST。
  - **シミュレーションLOD**（確定状態に影響する精度・更新頻度）: 判断入力は確定状態・権威化エントロピー由来に限る MUST。同一入力からは同一の段階選択となり、決定論を保存する。
  - **プレゼンテーションLOD**（描画解像度・カリング等、出力のみ）: 実行時計測 $M(t)$ や注視点距離に依存してよい MAY。確定状態には一切影響しない MUST。
- **実体化制御（旧 Schrödinger's Culling）**: 全観測領域外のエンティティは個別演算を停止し、マクロ要約分布へ圧縮してよい MAY。観測時に $O(1)$ 相当で再実体化できること SHOULD。
- **密度上限時の相転移**: 局所密度が閾値を超えた場合、低優先個体を要約分布へ吸収し、資源上限内で演算継続する SHOULD（無制限成長でのクラッシュ防止）。
- **階層型ストレージ（Hot / Warm / Cold）**: 常時参照される作業集合を高速メモリ（Hot）に、待機状態を主記憶（Warm）に、長期退避分を外部ストレージ（Cold）へ段階配置してよい MAY。Cold への退避・読み戻しはメイン更新をブロックしないチャンク単位の非同期 I/O とする SHOULD。

### 4.2 空間索引 & 階層（Spatial Index / Hierarchy）

- 契約: 近傍・可視範囲・相互作用対象を平均 $O(1)$〜$O(\log n)$ で抽出する。
- 手法（空間ハッシュ、グリッド、木、Morton 順序等）はプロファイル裁量。**境界抜け（トンネリング）を起こさない**近傍完全性を満たす MUST。
- **階層伝播**: 親子連結を持つドメインでは、親確定後に子を評価する順序（トポロジカル整列）で1フレーム遅延を排除する MUST。
- **局所性最適化**: 索引順に実データを周期的に再配置し、参照局所性を高めてよい MAY。

### 4.3 スケジューラ & 時間制御（Scheduler / Time Dilation）

- 契約: Tick 進行と、エンティティ／領域ごとの更新頻度配分を管理する。
- **局所時間拡張**: 変動強度に比例して更新頻度を可変化し、静穏領域は間欠更新へ落とす MAY。頻度を決める判断入力は**確定状態由来**（例: 変動Δ）に限り、実測フレーム時間等に依存しないこと MUST。これにより同一入力から同一の更新スケジュールとなり決定論を保存する。
- **稠密化（Stream Compaction 等）**: 実行対象を密なリストへ圧縮し遊休スレッドを削減してよい MAY。

### 4.4 入力パイプライン（Action Ingestion）

- 契約: 入力を**ゼロ／低アロケーション**で取り込み、Tick へ確定的に割り付ける。固定容量リングバッファ推奨 SHOULD。
- すべての非決定的入力（乱数・現実ノイズ）は、コアへ渡る前に**シード化・権威化**され、$\varepsilon_t$ の一部として確定する MUST（§5）。

### 4.5 出力アダプタ（View / Output）

- 契約: 確定状態を外部表現（描画・ログ・エクスポート）へ写像する。**コアに対して読み取り専用**であり状態を変えない MUST。
- 大量エンティティの可視化では、中間オブジェクトを介さない直接束縛・不要描画の除外（可視性/遮蔽カリング）等でアロケーションと過描画を抑制する SHOULD。
- 出力は副作用のため、決定論検証の対象外に置いてよい MAY。

### 4.6 予測 & 探索（Prediction / Shadow）

- 契約: 本番タイムラインを汚染せず、現在スナップショットの複製上で未来を試行する。
- 探索対象は**影響範囲（Cone of Influence）**に極小化し、範囲外は静的近似としてよい SHOULD（資源保護）。
- 長時間探索は**時間分割（Time Slicing）**で複数フレームへ分散し、メイン更新のレートを損なわない MUST。
- 探索結果の本番反映は明示的な確定点でのみ行う MUST。

### 4.7 ネットワーク（Network・任意）

- 契約（任意能力）: 複数ノードで空間/状態を分担する場合の同期。
- **状態全体ではなく入力列を共有**する決定論的ロックステップ、または権威サーバ方式のいずれかを選ぶ MUST。ローカル全状態のブロードキャストは禁止 MUST NOT。
- レイテンシ吸収に楽観実行＋巻き戻し再計算（ロールバック）を用いてよい MAY。巻き戻しは§4.8 の履歴に依存する。
- トポロジ（P2P/DHT/Geohash/権威）はプロファイル裁量。

### 4.8 履歴 & 決定論（History / Determinism）

- 契約: 時間遡行と再計算の基盤。**全状態の逐次保存を禁止**し（コスト過大）、初期シード＋入力列＋エントロピー確定タイミングのみを記録する MUST。
- 任意の確定 Tick へは、記録列からの再計算のみで到達できる MUST（§1 原則5）。
- **数値決定論**: 複数の異種ハードウェア間で同期する構成では、浮動小数点の非決定的丸めを避け、固定小数点等のビット決定的演算を用いる MUST。単一ノード完結ならこの限りでない MAY。

## 5. 環境エントロピーの収穫・正規化・権威化（$\varepsilon$）

現実ノイズをシミュレーション入力へ取り込む場合、決定論を破壊しない手続きを MUST で踏む。

1. **収穫（Harvest）**: 外部信号（デバイス負荷、センサ値、外部 API スパイク等）を独立プロセス／デーモンで取得し、メイン更新を阻害しない SHOULD。
2. **正規化（Normalize）**: 時間ローリング平均等で恒常的偏り（カオス化・熱的死）を抑え、相対スパイクのみ抽出する SHOULD。
3. **権威化（Authorize）**: 分散構成では、各ノードのローカル値を直接演算へ混入することを禁止 MUST NOT。合意された単一の真実（例: セクター・リーダーによる「Tick N の公式エントロピー」）としてのみ注入する MUST。
4. **拡散（Diffuse・任意）**: 過剰エントロピーを隣接ノードへ拡散し、メッシュ全体のマクロ均衡を保ってよい MAY。

収穫値の**意味付け**（どの信号を Dynamics のどの外因へ写すか）は L4 ドメインプロファイルの責務である。

## 6. Dynamics 契約（$D$・L2）

`Dynamics` は「状態変化に付与する動的性質」の**抽象契約**であり、具体モデルはドメインが与える。

契約が要求する概念（名称は一般化）:

| 概念 | 一般的意味 | 要件 |
| --- | --- | --- |
| Potential（勢い） | 変化の方向と大きさのポテンシャル | 量子化・スナップショット可能 MUST |
| Excitation（強度） | 一時的・可逆な励起／熱量 | 減衰則を定義 SHOULD |
| Accumulation（蓄積） | 長期・不可逆な累積（劣化・疲労の一般化） | 単調非減少、可逆性はスナップショット経由でのみ MUST |
| Interaction（相互作用） | 近傍間の伝搬・衝突解決 | 並行更新時の競合を回避（ダブルバッファ／原子演算等）MUST |

> **注**: v1.0.0 の **VIF（Velocity / Intensity / Fatigue）** は、この契約の (Potential, Excitation, Accumulation) への一具体写像である。VIF はコアではなく、ABC ドメインプロファイル（§8）が提供する Dynamics 実装として扱う。

相互作用の数値解法（例: マルチパス・ヤコビ反復による競合回避）は機構／プロファイルの裁量だが、**確定的なマクロ挙動**を保証する MUST。

## 7. 実行プロファイル（L3）

同一の抽象コアを、複数バックエンドへ束縛する。プロファイルは各機構契約(§4)の具体実装を提供し、**適合性（§9）を宣言**する MUST。

### 7.1 参照プロファイル A: ブラウザ / WebGPU

- 計算: WebGPU Compute Shader（WGSL）。空間索引に Morton 順序＋GPU ソート、27近傍探索。データ再配置パスで局所性最適化。
- メモリ: `Uint32Array` 系ビットパック SoA を GPU Storage Buffer に常駐、固定容量プール。
- 履歴: GPU 内リングバッファのみで完結し CPU-GPU I/O を排除。
- 描画: 二段遮蔽カリング＋間接ディスパッチ／間接ドロー（CPU は発行のみ）。
- 予測: MCTS を独立 Compute Pipeline へオフロード、差分トラッキング＋時間分割。
- 転送: WebRTC P2P メッシュ（空間トポロジ認識ルーティング、任意）。

### 7.2 参照プロファイル B: Python エコシステム（`wgpu-py` 基盤）

- ユーザー API: テンソル演算ベースの制約付き DSL（遅延評価グラフ）→ WGSL へ自動コンパイル。`if` 直書きではなく `where` 等でスレッド分岐を排除。
- バックエンド差し替え: **Native WebGPU（主）／ Taichi・JAX（科学計算・ML 連携）／ NumPy（GPU 無し・CI フォールバック）**。同一ビット制約を CPU 上でエミュレート。
- 連携: 履歴バッファを `numpy.ndarray` / PyTorch `Tensor` へゼロコピー（最小コスト）でマッピングし、学習データへ即接続。
- I/O: ステージングのトリプルバッファリングによる Fire-and-Forget 非同期転送。
- エントロピー: `multiprocessing.shared_memory` を用いた独立デーモン（Shadow Harvester）。

### 7.3 参照プロファイル C: CPU 参照実装（Conformance Baseline）

- 目的: 仕様の**規範的リファレンス**。全機構を単純な逐次 CPU 実装で提供し、他プロファイルの決定論を照合する黄金基準とする。
- 数値: 固定小数点演算で A/B と**ビット等価**な結果を出す MUST。GPU 無し環境・テスト・監査用途。

> 準拠を主張する実装は、代表シナリオで**プロファイル C とビット等価**であることを検証する SHOULD。

## 8. ドメインプロファイル（L4）— 参照例: ABC / VIF

ドメインプロファイルは、論理スキーマ・遷移規則・Dynamics 写像・エントロピー意味付けを与える。ABC は数ある適用先の**一例**である。

### 8.1 ABC 論理スキーマ（参照）

エンティティの ABC 状態を 32bit へパックする一具体化。

| ビット | フィールド | 意味 |
| --- | --- | --- |
| `[0-1] vA` / `[2-3] vB` / `[4-5] vC` | 強度（各2bit） | ABC 各軸のポテンシャル |
| `[6-11] dA` / `[12-17] dB` / `[18-23] dC` | 変動Δ（各6bit・符号付） | 各軸の変化量（Excitation の源） |
| `[24-26] State`（3bit） | 特殊状態フラグ | アクティブ/非アクティブ、プロモート状態等 |
| `[27-29] RuinScore`（3bit） | 累積破綻値 | Accumulation（不可逆劣化） |
| `[30-31] Reserve`（2bit） | 予約 | 拡張用 |

- **動的ビット解像度プロモーション**: 注視中心／高カオス領域の個体を一時的に 64bit（VIF 各8bit、Δ 各16bit）へ昇格し、安定化・観測外で 32bit へ降格。
- **物理座標の分離**: 座標・速度は ABC パックとは別の固定小数点 SoA（16.16／昇格時 32.32）として持ち、精度とメモリ効率の矛盾を解消。

### 8.2 ABC の Dynamics 写像

- Potential ← ABC 強度（vA/vB/vC）
- Excitation ← 変動Δ（dA/dB/dC）による熱量
- Accumulation ← `RuinScore`（不可逆ダメージ）
- 相互作用 ← 密集時のマルチパス・ヤコビ反復（Ping-Pong／原子演算）

### 8.3 ABC のエントロピー意味付け（参照）

ABC ドメインは外部環境要因を **E0〜E3** の系統で表す（E0: 基底／外力なし、E1: 過酷環境、E2: 社会圧・評価圧、E3: ノイズ）。§5 で収穫・権威化した現実ノイズを次のように写像する。

- デバイス負荷（CPU 温度・バッテリ変動）→ 外因 $E1$（過酷環境）
- 環境ノイズ（マイク入力の dB 値・環境光）→ 外因 $E3$（ノイズ）
- 外部 API スパイク → 外因 $E2$（社会圧・評価圧）
- **地形化（旧「死骸の地形化」）**: `Zero-Lock`（破綻）個体は動的計算から除外し、空間グリッド上の $E2$/$E3$ 定数ソースへ転化。

> 別ドメイン（粒子物理、群衆流動、経済シミュレーション等）は、同じ機構契約(§4)の上で**別の論理スキーマと Dynamics 写像**を差し込むだけで構築できる。これが v2.0.0 の汎用性の核心である。

## 9. 適合性レベル（Conformance）

準拠実装は、達成レベルを宣言する MUST。

| レベル | 必須機構 | 想定用途 |
| --- | --- | --- |
| **Core** | §2 核タプル、§2.2 決定論的遷移、§3 論理スキーマ、§4.4 入力、§4.8 履歴（入力ロギング＋再計算） | 単一ノード・単一スレッドの決定論シミュレーション |
| **Standard** | Core + §4.1 LOD/量子化、§4.2 空間索引/階層、§4.3 スケジューラ、§4.5 出力、§6 Dynamics | 実時間の大規模単機シミュレーション／可視化 |
| **Full** | Standard + §4.6 予測、§4.7 ネットワーク、§5 権威化エントロピー、§4.8 数値ビット決定論 | 分散・P2P・自律介入を含む本格運用 |

**適合性の検証（SHOULD）**

- 同一シード・同一入力列で**再現性テスト**（同一実装内でのビット等価な再計算）。
- 代表シナリオで**プロファイル C（CPU 参照）とのビット等価照合**。
- LOD 段階を切り替えても**コア意味論が保存**されること（マクロ指標の許容誤差内一致）。

## 10. システムフロー（Standard 準拠の代表例）

1. **スキーマ生成**: 論理スキーマ → レイアウト／アクセサをコンパイル（§3.2）。
2. **エントロピー確定**: 収穫→正規化→権威化し、Tick N の $\varepsilon_N$ を確定（§5）。
3. **入力確定**: 入力をリングバッファへ低アロケーションで取り込み、Tick へ割付（§4.4）。
4. **スケジューリング**: $M(t)$ に基づき LOD 解像度と更新頻度を決定、実行対象を稠密化（§4.1, §4.3）。
5. **階層演算**: トポロジカル順で親→子を確定的に更新、Dynamics を適用（§4.2, §6）。
6. **（任意）未来探索**: 影響範囲内で予測を時間分割実行（§4.6）。
7. **状態確定**: Tick ID で確定。分散時は入力列合意で不整合を再計算補正（§4.7, §4.8）。
8. **出力**: 読み取り専用アダプタで描画／エクスポート（§4.5）。
9. **退避**: 温度に応じ Cold ストレージ／要約分布へ非同期退避（§4.1）。

## 12. まとめ

v2.0.0 は、v1.0.0 系が実質的に「WebGPU × ABC ゲーム／シミュレーション専用設計」であった点を検証し、**不変の抽象コア（決定論・データ指向・段階的詳細度・明示的制約・可逆性）** と、**差し替え可能な実行／ドメインプロファイル**へ層分離した。これにより:

- 形式モデルは版・環境によらず**7要素で不変**となり、旧3版の不整合を解消した。
- WebGPU/WGSL/WebRTC/32bit-ABC は**参照プロファイル**へ退避し、CPU・他バックエンド・他ドメインへ**真に汎用**に適用できる。
- **適合性レベルと機構契約**により、最小実装から分散フル実装までを段階的・検証可能に構築できる。

資源制約を技術的優位へ転換するという UCD-F の思想は保ちつつ、その適用範囲を単一のドメイン／実装から解放したものが本 Universal Core v2.0.0 である。
