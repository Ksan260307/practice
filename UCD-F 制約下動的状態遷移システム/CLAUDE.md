## プロジェクト概要

UCD-F は「厳しい資源制約（メモリ・権限・計算資源）を、決定論・データ指向・段階的詳細度によって
技術的優位へ転換する」汎用シミュレーション・フレームワーク。特定の実行環境やドメインに依存しない
**抽象コア**と、差し替え可能な**プロファイル**に層分離されている。

```
L4 ドメインプロファイル   状態スキーマ・遷移規則・Dynamics写像（例: ABC/VIF）      差し替え可
L3 実行プロファイル       計算/描画/転送バックエンド（WebGPU / Python / CPU参照）  差し替え可
L2 機構契約              メモリ/空間索引/スケジューラ/履歴/出力/予測/転送の抽象IF  契約のみ
L1 抽象コア              形式モデル・決定論・状態遷移の意味論                      規範・不変
```

- **L1/L2 を変更するときは Universal Core の改訂を伴う**。安易に触らない。
- 新機能は原則 **L3/L4（プロファイル）側**に足す。コアの汎用性を壊さないこと。

## 絶対に守る不変条件（Invariants）

作業がこれらに違反していないか、コード変更・レビューのたびに確認すること。

1. **決定論優先**: 同一シード＋同一入力列 → 全準拠実装でビット等価な状態列。
2. **データ指向**: 状態は論理スキーマとして実装から独立に定義。物理表現（SoA/ビットパック/GPU常駐）はプロファイル裁量。
3. **段階的詳細度**: 負荷に応じ精度・頻度・実体化度を落としてよいが、コア意味論を壊さない。
4. **明示的制約**: 資源・権限の制約はモデルの一級要素 `C`。暗黙に踏み越えない。
5. **可逆性**: 任意の確定 Tick へ、記録した入力列からの**再計算のみ**で到達可能（全状態の逐次保存は禁止）。

### 決定論を壊す典型的な落とし穴（レビュー必須チェック）

- ❌ 遷移関数 `C` の中で `Date.now()` / 実測フレーム時間 / 未シードの乱数 / 生センサ値を直接読む。
- ❌ **シミュレーションLOD**（確定状態に影響する精度・更新頻度・時間拡張）を実行時計測 `M(t)`（wall-clock, CPU温度, 実測fps）で駆動する。
      → 判断入力は**確定状態・権威化エントロピー由来**に限る。
- ❌ 分散構成でローカル状態全体をブロードキャストする／各ノードが生エントロピーを直接演算へ混入する。
      → 共有するのは**入力列**のみ。エントロピーは**権威化**（単一の真実として合意）してから注入。
- ❌ 異種ハードウェア間同期で `f32` 等の非決定的丸めに依存。→ 固定小数点（16.16 等）を使う。
- ✅ **プレゼンテーションLOD**（描画解像度・カリング等、出力のみ）は `M(t)` 依存でよい。確定状態に影響しないこと。

### 遷移関数 `C` の契約

```
S_{t+1} = C(S_t, A_t, D, ε_t)
```
- `C` は**純粋関数** MUST（副作用・I/O・描画・暗黙乱数なし）。乱数は `ε_t` の明示シードから決定論的PRNG（PCG系ハッシュ等）のみ。
- 時間は離散 **Tick**（整数ID）。全ノード・全観測者は同一 Tick で同一 `C` を適用。
- `B`（露出制御）は確定状態を変えない。`M`（計測）は確定状態へ影響する判断に使わない。

## 形式モデル（核タプル・不変）

```
Core = (S, A, C, B, D, M, ε)
```
| 記号 | 意味 |
| --- | --- |
| S | State（論理状態 or 非実体領域の要約分布） |
| A | Action（入力：ユーザー入力・権威化エントロピー・ネットワーク入力） |
| C | Constraint & Core（資源/権限制約と、それを尊重する遷移規則 TR） |
| B | Bank（権限・観測に応じた露出制御。状態は変えない） |
| D | Dynamics（力学契約：Potential/Excitation/Accumulation/Interaction） |
| M | Metrics（表示適応の指標。状態影響判断には使わない） |
| ε | Environment（環境制約係数＋収穫・権威化された現実ノイズ） |

`Q/V/P/H/L/T/N`（量子化・出力・予測・階層・レイアウト・時間拡張・ネットワーク）は**核ではなく任意能力**。
機構契約（Universal Core §4）として実装し、必要なものだけ足す。

## Dynamics の書き方（ドメイン実装時）

`Dynamics` は抽象契約。ドメインは以下の写像を与える。
- **Potential（勢い）**: 変化のポテンシャル。量子化・スナップショット可能。
- **Excitation（強度）**: 一時的・可逆な励起／熱量。減衰則を定義。
- **Accumulation（蓄積）**: 長期・不可逆な累積（劣化・疲労）。単調非減少、可逆はスナップショット経由のみ。
- **Interaction（相互作用）**: 近傍伝搬・衝突解決。並行更新の競合を回避（ダブルバッファ／原子演算）。

> 参照ドメイン **ABC/VIF** は上記の一実装（VIF = Potential/Excitation/Accumulation の写像）。
> コアに ABC を埋め込まない。新ドメインは同じ機構契約の上に別スキーマ＋別写像を差すだけで作る。

## 適合性レベル（実装が宣言する）

| レベル | 必須機構 | 用途 |
| --- | --- | --- |
| **Core** | 核タプル＋決定論的遷移＋論理スキーマ＋入力＋履歴（入力ロギング＋再計算） | 単一ノード決定論シミュレーション |
| **Standard** | Core ＋ LOD/量子化・空間索引/階層・スケジューラ・出力・Dynamics | 実時間大規模単機／可視化 |
| **Full** | Standard ＋ 予測・ネットワーク・権威化エントロピー・数値ビット決定論 | 分散/P2P/自律介入を含む運用 |

新しい実装・変更は、**どのレベルを対象とするか**を明確にしてから着手する。

## 実行プロファイル（L3）

| プロファイル | バックエンド | 位置づけ |
| --- | --- | --- |
| A: ブラウザ/WebGPU | WGSL Compute・Morton空間ハッシュ・間接描画・WebRTC(任意) | 参照・実時間 |

| C: CPU参照 | 逐次CPU＋固定小数点 | **決定論の黄金基準**。A/B とビット等価 |

- 決定論を主張する変更は、代表シナリオで **プロファイル C とのビット等価**を照合する SHOULD。
- 既存 `src/` の各アプリは特定プロファイル/ドメインの実験実装。横断変更時は該当プロファイルの契約を壊さないこと。

## 検証（変更を確定する前に）

- **再現性テスト**: 同一シード・同一入力列で再計算し、ビット等価を確認。
- **参照照合**: 可能なら CPU 参照（プロファイル C）と突き合わせる。
- **LOD保存**: LOD 段階を切り替えてもマクロ指標が許容誤差内で一致（コア意味論の保存）。
- 決定論に触れる変更は、上記なしにマージしない。
