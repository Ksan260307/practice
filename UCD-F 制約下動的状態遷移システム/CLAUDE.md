## プロジェクト概要

UCD-F は「厳しい資源制約（メモリ・権限・計算資源）を、決定論・データ指向・段階的詳細度によって
技術的優位へ転換する」汎用シミュレーション・フレームワーク。特定の実行環境やドメインに依存しない
**抽象コア**と、差し替え可能な**プロファイル**に層分離されている。

```
L4 ドメインプロファイル   状態スキーマ・遷移規則・Dynamics写像（例: ABC/VIF）      差し替え可
L3 実行プロファイル       計算/描画/転送バックエンド（WebGPU / Python / CPU参照）  差し替え可
L2 機構契約              メモリ/空間索引/スケジューラ/入力/露出/出力/予測/転送/履歴 契約のみ
L1 抽象コア              形式モデル・決定論・状態遷移の意味論                      規範・不変
```

- **L1/L2 を変更するときは Universal Core の改訂を伴う**。安易に触らない。
- 新機能は原則 **L3/L4（プロファイル）側**に足す。コアの汎用性を壊さないこと。

## 形式モデル（不変）

区分基準は「**確定状態を決定するか否か**」の一点のみ。

```
確定核 Core = (S, A, C, D, ε)     ← 確定状態の軌跡を決める
観測層 Obs  = (B, M, V)           ← 確定状態を一切変えない
S_{t+1} = C_D(S_t, A_t, ε_t)      ← D は C をパラメータ化する時不変契約（Tick入力ではない）
```

| 記号 | 意味 |
| --- | --- |
| S | State（論理状態 or 非実体領域の要約分布） |
| A | Action（ユーザー入力・権威化された環境入力・ネットワーク入力・**観測者状態**） |
| C | Constraint & Core（資源/権限制約と、それを尊重する遷移規則 TR） |
| D | Dynamics（Potential/Excitation/Accumulation/Interaction。**Core から必須**） |
| ε | Environment（環境制約係数＋収穫・権威化された環境ノイズ） |
| B | Bank（権限・観測に応じた露出制御。**信頼境界**） |
| M | Metrics（**表示適応**の指標。状態影響判断には使わない） |
| V | View / Output（出力。読み取り専用） |

`Q/P/H/L/T/N`（量子化・予測・階層・レイアウト・時間拡張・ネットワーク）は**核でも観測層でもない任意能力**。

### 遷移関数 `C_D` の契約

- **純粋関数** MUST（副作用・I/O・描画・暗黙乱数なし）。乱数は `ε_t` の明示シードから決定論的PRNG のみ。
- **順序独立性 MUST** — 同一世代内の**評価順序・並列分割によらず同一結果**。
  例外は §4.2 の階層伝播が定める世代間順序（親→子）のみ。
  ⚠️ **純粋であることは順序独立性を含意しない**。ここを取り違えるとデータ再配置・稠密化・並列化が全部壊れる。
- 時間は離散 **Tick**（整数ID）。複数の演算主体があるなら、全主体が同一 Tick に同一 `C_D` を適用。
- 観測層 `(B, M, V)` は遷移式に現れない。確定状態へ影響させてはならない。

## 絶対に守る不変条件（Invariants）

1. **決定論優先** — 二段階。混同しないこと。
   - **再現性**（全レベル必須）: 同一実装・同一**再生同一性**・同一シード・同一入力列 → ビット等価。
   - **実装間ビット等価**（宣言制・Full必須）: 数値決定論（固定小数点等）を採用した実装のみ主張可。
   - **主張の有無が再生同一性の構成を変える**（下記「履歴・再生」参照）。
2. **データ指向**: 状態は論理スキーマとして実装から独立に定義。物理表現はプロファイル裁量。
3. **段階的詳細度**: 負荷に応じ精度・頻度・実体化度を落としてよいが、**適応の2分類**（下記）を厳守。
4. **明示的制約**: 資源・権限の制約はモデルの一級要素 `C`。暗黙に踏み越えない。
5. **可逆性**: 記録した（**再生同一性**, 初期シード, 入力列）からの**再計算のみ**で任意の確定 Tick へ到達可能。

## 最重要 1: 並列実行と決定論（v1 以来の最大の穴）

> **競合（data race）の回避と決定論は別問題。** 原子演算はレースを防ぐが、**適用順序の非決定性は防がない**。

| 手段 | 順序依存性 | 可否 |
|---|---|---|
| **ダブルバッファ**（ヤコビ反復・Ping-Pong） | 読み書き分離で**順序独立** | 常に可 |
| **原子演算** | 適用順序が**非決定的** | **結合律・交換律を満たす演算に限る** |

- ✅ 整数加算（法 2ⁿ 含む）・XOR・min/max への原子演算 → 順序が変わっても結果同一。安全。
- ❌ **浮動小数点加算への `atomicAdd`** → `(a+b)+c ≠ a+(b+c)`。**同一実装・同一入力でも実行ごとに結果が変わり、再現性(全レベル MUST)が壊れる**。
- ❌ 非結合な演算を、順序が保証されない文脈で累積する。
- 🔍 **順序独立性検証**（全レベル MUST）: 評価順序をシャッフルして結果不変か確認。
  逐次実装でも反復順序を入れ替えるだけででき、**最も費用対効果が高い**。これが落ちたら float atomics を疑う。

## 最重要 2: 適応の2分類

| | シミュレーション適応 | 表示適応 |
|---|---|---|
| **何を変える** | 確定状態（精度・更新頻度・実体化） | 出力のみ（描画解像度・視錐台/遮蔽カリング） |
| **判断入力** | **確定状態・権威化された入力のみ** | 実行時計測 `M(t)`・実行時カメラ 可 |
| **例** | 観測外カリング、精度昇格、時間拡張、強制要約化 | 描画LOD、遮蔽カリング |

- ❌ `C_D` の中で `Date.now()` / 実測フレーム時間 / 未シードの乱数 / 生センサ値を直接読む。
- ❌ シミュレーション適応を `M(t)`（wall-clock, CPU温度, 実測fps）で駆動する。
- ❌ **観測外カリングや精度昇格を、表示専用カメラ／注視点で駆動する。**
      → 確定状態を変える＝シミュレーション適応。分散では**各主体の視界差で状態が分岐**。
- ✅ 観測に基づく最適化をするなら、**観測領域を「観測者状態」として確定状態（権威化された入力 A）に含める**。
      **確定観測領域 = 全観測者の観測領域の合併**。この合併が**全演算主体で一致**すること。
      （「全員が同じ場所を見ろ」ではない。各人の視界は自由、合併の計算結果が一致すればよい）
- ✅ 同じ「カリング」でも、**観測外カリング（状態を変える／確定観測領域で駆動）** と
      **視錐台・遮蔽カリング（出力のみ／実行時カメラで駆動）** は別パス。統合してはならない。
- 🔍 **適応分離検証**（Standard以上 MUST）: **入力列（観測者状態含む）を固定したまま**、
      実行時計測と表示層カメラだけ変えて確定状態列が不変か確認。入力列を固定するのが要点。

### 用語: 観測者 ≠ 演算主体

- **観測者（Observer）**: 露出・観測の主体。1つの演算主体が**複数保持しうる**。露出制御は観測者ごと。
- **演算主体（Compute Subject）**: `C_D` を実行して確定状態を進めるノード／プロセス。状態一致は演算主体ごと。

## 履歴・再生

- 一次履歴 = **再生同一性 + 初期シード + 入力列**（観測者状態・介入含む、Tick ID 付き）。
  確定状態の逐次永続化を一次履歴にしてはならない。
- **再生同一性は適合性依存**。ここが対称になっていないと壊れる:

| 構成 | 実装識別子（プロファイル+実装版） |
|---|---|
| **ビット等価を主張しない**（f32 可。Core/Standard 既定） | 再生同一性に**含める MUST** |
| **ビット等価を主張する**（数値決定論採用。Full 必須） | 再生同一性に**含めない MUST NOT** |

- ❌ 主張しないのに実装識別子を**含めない** → 別実装のログを拒否できず、**再現不能な再生を黙って受理**。
- ❌ 主張するのに実装識別子を**含める** → A のログを C で再生する基準実装照合が**不能**になり、
      ビット等価な A+B 混成メッシュも禁止されてしまう。**プロファイルは変わってよい軸**。
- ❌ 履歴に再生同一性（スキーマ版 / `C_D` 版 / Dynamics版 / 数値表現）を含めない。
      → `C_D` を1行変えた瞬間に旧ログの再生結果が変わる。不一致ログは**再生を拒否 MUST**。
- ❌ チェックポイントに権威を持たせる／破棄すると壊れる設計にする。
      → **最適化であって前提ではない**（全レベル MAY）。可逆性・蓄積の巻き戻し・探索起点は
        すべて**一次履歴からの再計算のみで成立**すること。

## 分散

- ❌ ローカル確定状態の全体をブロードキャストする／各主体が生エントロピーを直接演算へ混入する。
      → 共有するのは**入力列**のみ。複数演算主体があるなら**権威化**してから注入。
      （単一主体なら権威化は行わなくてよい。ただし**シード化・記録は全構成で必須**）
- 観測者状態の共有は**条件付き**: シミュレーション適応に使うなら共有 MUST／
  表示適応にしか使わないなら共有すべきでない SHOULD NOT（不要な視線露出を避ける）。
- ❌ 異種ハードウェア間同期で `f32` 等の非決定的丸めに依存。→ 固定小数点（16.16 等）。

## 露出制御（Bank）は信頼境界

- 非露出フィールドは**出力・送出のいずれの経路からも漏出させない**。要約分布へ圧縮した領域にも同等に適用。
- 露出判定は（確定状態, 観測者権限）のみの関数。既定は**拒否**。
- ⚠️ 予測が非露出情報で介入を決めると、結果経由で情報が漏れる（サイドチャネル）。
- ⚠️ **既知の残存リスク**: 観測者状態は確定核の入力で **Bank の管轄外**。観測に基づく適応を使う構成では
  「誰がどこを見ているか」は秘匿されない。対戦型等で秘匿が要件なら、観測ベース適応を採らないか
  領域の粒度を粗くするなど**ドメイン設計側で対処**する。露出制御では解決できない。

## Dynamics の書き方（ドメイン実装時）

`D` は確定核の要素なので **Core レベルから必須**。
- **Potential（勢い）**: 変化のポテンシャル。量子化可能。
- **Excitation（励起）**: 一時的・可逆な励起量。減衰則を定義。
- **Accumulation（蓄積）**: 長期・不可逆。**単調非減少**。減少は**一次履歴からの再計算**による巻き戻しでのみ。
- **Interaction（相互作用）**: 近傍伝搬・衝突解決。競合回避は上記「最重要1」の制約に従う。
  相互作用が無いドメインは空と宣言してよい。

> 参照ドメイン **ABC/VIF** は上記の一実装。コアに ABC を埋め込まない。
> 新ドメインは同じ機構契約の上に別スキーマ＋別写像を差すだけで作る。

## 適合性レベル（実装が宣言する）

達成レベルと、**実装間ビット等価を主張するか否か**の両方を宣言すること。

| レベル | 必須機構 | 用途 |
| --- | --- | --- |
| **Core** | 確定核＋決定論的遷移＋**順序独立性**＋論理スキーマ/版＋入力＋**Dynamics**＋一次履歴/再生同一性＋**再現性** | 単一ノード決定論シミュレーション |
| **Standard** | Core ＋ メモリ/LOD・空間索引/階層・スケジューラ・**露出制御**・出力 | 実時間大規模単機／可視化 |
| **Full** | Standard ＋ 予測・ネットワーク・権威化・数値決定論＋**実装間ビット等価** | 分散/P2P/自律介入を含む運用 |

- **チェックポイントは全レベルで任意（MAY）**。実装する場合のみ仕様に準拠。
- 新しい実装・変更は、**どのレベルを対象とするか**を明確にしてから着手する。

| プロファイル | バックエンド | 位置づけ |
| --- | --- | --- |
| A: ブラウザ/WebGPU | WGSL Compute・空間充填曲線索引・間接描画・WebRTC(任意) | 参照・実時間 |

## 検証（変更を確定する前に）

| 検証 | 対象 |
| --- | --- |
| **再現性テスト**（同一シード・同一入力列でビット等価） | 全レベル必須 |
| **順序独立性検証**（評価順序・並列分割を変えてビット等価） | 全レベル必須 |
| **版検査**（再生同一性が不一致のログの再生を拒否） | 全レベル必須 |
| **実装識別子検査**（別実装のログの再生を拒否） | ビット等価を主張**しない**場合 |
| **メタデータ非干渉**（プロファイルのみ違うログを拒否**しない**） | ビット等価を主張**する**場合 |
| **適応分離検証**（入力列固定で、負荷・カメラだけ変えてビット等価） | Standard 以上 |
| **露出検証**（非露出フィールドが出力・送出から漏れない） | Standard 以上 |
| **チェックポイント等価**（再開結果 = 全再計算結果） | 実装する場合のみ |
| **確定観測領域の一致**（合併が全演算主体で一致） | Full 必須 |
| **基準実装照合**（プロファイル C とビット等価） | Full 必須 |

- 実装識別子検査とメタデータ非干渉は**排他**（主張の有無でどちらか一方のみ適用）。
- 決定論・露出に触れる変更は、上記なしにマージしない。
- **順序独立性検証**と**適応分離検証**は、原則1/原則3 違反を機械的に炙り出せる。
  LOD/カリング/スケジューラ/相互作用を触ったら必ず回すこと。
